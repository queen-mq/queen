Four programs that show what the Queen queue connection does inside a Laravel worker. Each one is
an Artisan command that starts real `php artisan queue:work` workers, or `php artisan
queen:supervise`, prints what they did, and ends with `PASS` or `FAIL`.

## Run them

You need Docker for the broker, PHP 8.3 or later with the `pcntl` and `posix` extensions, and
Composer.

```bash
docker run -d --name queen -p 6632:6632 ghcr.io/queen-mq/queen:latest
git clone https://github.com/queen-mq/queen
cd queen/examples/apps/laravel
composer install
php artisan example:ordering   # or example:prefetch, example:prefork, example:lease
```

- **All four at once:** `examples/apps/run.sh laravel`, from the root of the clone. It installs
  the application's dependencies when they are missing and reinstalls the PHP client from the
  clone, so the examples run the client of your checkout.
- **Another broker:** every command reads `QUEEN_URL` (default `http://localhost:6632`).
- **No database, no Redis:** the application uses Laravel's file cache and no failed-jobs table.

We ran them on an Apple-silicon laptop with PHP 8.4.25, Laravel 12.69.3 and PHP client 2.3.0 from
the repository, against a 2.0.1 node in Docker (the amd64 image, emulated). `run.sh laravel` ran
the four in about 40 seconds: 3 for ordering, 10 for prefetch, 4 for prefork and 24 for lease
(2026-10-06). We also ran them on Linux, with PHP 8.3.35 in Docker, where `example:prefork` also
measures each worker's private memory.

## What the application holds

| File | What it holds |
| --- | --- |
| `config/queue.php` | the four Queen connections the examples use |
| `config/queen.php` | the two supervisor pools of `example:prefork` |
| `app/Jobs/` | one job class per example |
| `app/Console/Commands/Examples/` | the four programs |
| `app/Examples/` | what they share: workers, job records, checks |

The connections differ only in the keys an example needs. Every Queen connection takes the rest
from `config/queen.php`, and that file takes what it does not set from the package.

## What they have in common

- **Real processes.** Each worker is its own PHP process. The jobs write one JSON line per event
  to `storage/examples/<queue>.jsonl`, the one place every process can write to, and the
  program reads that file to check what happened.
- **Fresh queues.** Each run uses queue names no earlier run used, so two runs never see each
  other's jobs.
- **Waits with a deadline.** A program waits for a condition, such as "every job has run", and
  fails after a deadline. No step waits for a fixed time.
- **Checks and an exit code.** A run ends with `PASS: N checks` and exit code 0, or with `FAIL`,
  the reason and the output of every worker, and a non-zero exit code.
- **Clean up after a pass.** A passing run deletes its queues and its files. A failing run keeps
  them, for you to read.
