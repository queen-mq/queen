QueenMQ is built at Smartness and developed in the open. The broker, the clients, the dashboard, the Laravel driver, the benchmarks and these docs live in one repository, [github.com/queen-mq/queen](https://github.com/queen-mq/queen), under the [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0).

## These docs and the book

These pages follow [the little book of QueenMQ](/book/), written by the authors of QueenMQ and free to download as a PDF, chapter by chapter: [introduction](/introduction/), [writing applications](/writing-applications/), [patterns](/patterns/), [integrations](/integrations/), [managing clusters](/manage/) and [architecture](/architecture/). The book shows its code in JavaScript; these pages show the same code in all six languages of the SDKs. Every piece of code comes from a program that runs it against QueenMQ 2.6.0 and checks the result (`examples/tutorials/run.sh`), and the drawings are the book's own.

<Why>a sentence about a running system goes stale the day the code changes. Code that runs in a test, and pages that name the source files they describe, are how we notice. A check fails the docs build when a page is older than the code it names.</Why>

## Releases

The broker ships as one container image, `ghcr.io/queen-mq/queen`, for linux/amd64 and linux/arm64. Each release is on the [changelog](/reference/changelog/) and on [GitHub Releases](https://github.com/queen-mq/queen/releases), and the clients are on the registry of their language. Version 2.0.0 (2026-10-03) replaced the PostgreSQL storage of 1.x with QueenMQ's own log; security fixes go to 2.x only.

## Bugs, questions and features

Open an issue with one of the [issue templates](https://github.com/queen-mq/queen/issues/new/choose). For a bug, include the broker version, how you run it and the client you use. For a code change, open an issue first; [contributing](/architecture/contributing/) has the build, the tests and the rules.

## Security

Do not report a vulnerability in a public issue. Report it through [GitHub private vulnerability reporting](https://github.com/queen-mq/queen/security/advisories/new). How a deployment is secured is on [Security](/manage/security/).

## Maintainers and conduct

The maintainers are in [MAINTAINERS.md](https://github.com/queen-mq/queen/blob/master/MAINTAINERS.md), and [GOVERNANCE.md](https://github.com/queen-mq/queen/blob/master/GOVERNANCE.md) says how decisions are made. Everyone who takes part follows the [CNCF Code of Conduct](https://github.com/cncf/foundation/blob/main/code-of-conduct.md); report a violation privately to [conduct@queenmq.com](mailto:conduct@queenmq.com).
