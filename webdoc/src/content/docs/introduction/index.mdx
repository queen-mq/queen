  Queen MQ is a transactional event broker written in Rust: one binary per node, state in a log on
  the node's local disk, replicated with raft across a cluster of three or five nodes, and no
  external database (2.0 removed PostgreSQL). Every entity (a customer, an order, a conversation)
  gets its own ordered partition, created by the first message that names it, with no partition
  count to choose. One call to POST /api/v1/transaction acknowledges input, writes KV state, pushes
  the next events and schedules timers as one log entry: all of it applies or none of it does.
  Delivery is at-least-once; effects inside Queen are exactly-once through transactions and
  transactionId deduplication. Each tenant lives in exactly one raft group, so every transaction is
  one entry with no coordinator. Clients speak HTTP and JSON (SDKs for JavaScript, Python, Go, Rust,
  C++ and PHP), and Kafka clients can connect to a wire-protocol facade built into the broker.
  PostgreSQL tables stream in and out through built-in connectors, and an S3 sink writes queues to a

QueenMQ is a distributed message broker, built in Rust, replicated with Raft, and developed at Smartness. With it you can write applications that decouple producing from consuming, do request and reply, and process streams, using transactional features that let you remove a lot of logic from the application and offload it to QueenMQ.

Every feature the broker has is there because we needed it at Smartness, where it powers almost every product.

## In one picture

A worker takes a message, does its job, and then does several things at once: it finishes the message, saves some state, pushes the next events and asks for a reminder later. In most stacks those are four systems and four commits. In QueenMQ they are one call, written as one entry of the log, all or nothing.

<Fig id="one-step-one-commit" caption="One worker step without and with a transaction." />

<Why>a crash between two commits leaves a step half done, and somebody writes the code that finds those halves and repairs them. With one commit there is nothing to repair.</Why>
