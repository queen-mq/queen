KV (key/value state) holds the state a step changes, in the same replicated log as the messages,
so a KV write can commit with the ack that caused it. Use it for an entity's current state,
idempotency markers and counters. It is not a database: you read by key or by key prefix, and
nothing else.

## Operations

```js
await queen.kv.put('orders', '9137', { status: 'paid' }, { ttl: '30d' })
const row = await queen.kv.get('orders', '9137')   // { found, value, version, expiresAt, updatedAt }

const r = await queen.kv.put('orders', '9137', { status: 'shipped' },
  { ttl: '30d', expect: row.version })             // compare-and-swap
if (!r.applied) console.log(r.reason, r.value)     // someone wrote first

await queen.kv.incr('limits', `api:${customerId}:${minute}`, 1, { max: 100, ttl: '2m' })
```

```bash
curl -X POST http://localhost:6632/api/v1/kv -H 'content-type: application/json' -d '{"operations":[
  {"op":"put","ns":"orders","key":"9137","value":{"status":"paid"},"ttlSeconds":2592000},
  {"op":"get","ns":"orders","key":"9137"}]}'
```

| Op | Does |
|---|---|
| `get` | One key: `found`, `value`, `version`, `expiresAt`, `updatedAt`. `null` is a value: `found: true, value: null` is not absence. |
| `getMany` | Keys of one namespace: `rows` and an explicit `missing` list. |
| `getPrefix` | One page of keys under a non-empty prefix: `limit` (default 100, at most 1,000), `after` (keyset cursor), `nextAfter`. |
| `put` | Writes a value. Does not keep the previous TTL. |
| `putIfAbsent` | `put` with `expect: 0`. One concurrent caller wins; the losers get the winner's value and version. |
| `delete` | Removes a key, optionally with `expect`. |
| `incr` | Adds `delta` without a compare-and-swap loop. With `min` or `max`, an increment past the bound does not apply (`reason: "limit"`). The TTL is set on create only; an expired counter counts as zero. |

The answer is HTTP 200 with one result per op, in order. An absent key or a lost race is a
field in that result, not an error status. **Read `applied` on every write: the JS SDK returns
an object, and an object is always truthy.**

## Expiry: TTL or forever

Every `put`, `putIfAbsent` and `incr` declares exactly one of `ttlSeconds` (an integer above 0)
or `forever: true`; none or both is a 400 (`kv_expiry_not_specified`). The JS SDK also takes
`ttl: '30d'` or `until: date`. An expired key is never returned and never counts as existing,
even before the sweep removes it.

## Versions and `expect`

Every write gives the key a new version. Versions are unique and never reissued; do not rely on
their order. `expect: 0` means the key must not exist. `expect: N` means it must be at version
N, and writes nothing when the key is absent. A lost precondition answers `applied: false` with
`reason` `exists`, `absent` or `version`, plus the current value and version.

Other ops in the call still apply. Add `required: true` to make a lost precondition abort the
whole call: it answers HTTP 200 with `ok: false`, `reason: "kv_precondition"`, `failedIndex` and
`kvReason`.

## Consistency

- A read of one key is linearizable. A read-only call first waits until this node has applied
  everything the cluster had committed, so it sees a write another node answered.
- A call with writes is one log entry. Its reads see its own writes and nothing written after it.
- One call over several keys is strict serializable. `putIfAbsent` has one winner, and `incr`
  never loses or doubles an increment. These are [Jepsen-tested](/concepts/guarantees/).

## Inside a transaction

`queen.transaction().kv.put(...)` commits the write with the ack. When the ack carries its
lease, an expired lease undoes the write too (see [transactions](/concepts/transactions/)).
`get` and `getMany` are allowed there because you fix their cost; `getPrefix` is refused
(`kv_get_prefix_not_allowed_in_transaction`), because its read work has no bound inside a commit.
A transaction holds at most 64 KV ops and 256 keys.

## What KV is not

- **Not your business database.** No queries, no secondary indexes, no joins, no scan beyond a
  prefix page. Keep records you search in your database.
- **Not a lock.** `putIfAbsent` with a TTL expires; it is not revoked, and the old holder keeps
  working. Fence later writes with `expect` on the version you won.
- **Not free.** Every value travels the replicated log and is stored on every node.

## Limits

- **Names:** a namespace matches `^[a-z0-9][a-z0-9._-]{0,63}$` and belongs to one tenant; a key
  is non-empty, has no NUL and is at most 512 bytes (less with a long tenant and namespace).
- **Value:** any JSON up to 64 KiB, measured compact (`QUEEN_KV_MAX_VALUE_BYTES`). Set the
  ceiling the same on every node; above it the body and entry limits still apply.
- **One call** to `/api/v1/kv`: at most 256 ops and 1,024 keys (`QUEEN_KV_MAX_KEYS_PER_CALL`),
  one write per key, and 4 MiB of read results (past it, `truncated: true`).
- **Rate:** per tenant and per node, 100 write calls/s (burst 200) and 200 read calls/s (burst
  400) on `/api/v1/kv` by default (`QUEEN_KV_WRITE_RATE`, `QUEEN_KV_READ_RATE`). Over it you get
  429 with `Retry-After`.
- **`getPrefix` pages** are each their own snapshot: good for walking state, not for an exact
  count.
