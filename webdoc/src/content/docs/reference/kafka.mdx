Every Queen node can speak the Kafka wire protocol, so an unmodified Kafka producer or consumer
connects by changing `bootstrap.servers`. The facade is part of the binary and off by default.
Setup, client settings and a worked example are on [Kafka](/guides/kafka/).

```bash
QUEEN_KAFKA_EMBEDDED=true
QUEEN_KAFKA_ADVERTISED_ADDR=queen-0.example.internal:9092   # required: what clients reconnect to
QUEEN_KAFKA_ADDR=0.0.0.0:9092                               # the bind address (default)
```

- A Kafka topic is a Queen queue. Records go through the same push and fetch paths as native
  clients, and the facade keeps no durable state of its own.
- Committed offsets are stored as Queen consumer-group positions (`QUEEN_KAFKA_OFFSET_STORE`,
  default `positions`, or `kv`), so a Kafka group is also visible as a Queen consumer group.
- A client reads the ApiVersions answer first, so it never sends an API outside the table below.
- Authentication is SASL/PLAIN carrying a Queen bearer token; there is no SCRAM and no ACL model.

## Limits

- The Jepsen pass behind [guarantees](/concepts/guarantees/) ran on the native HTTP API. It did not
  cover the Kafka facade.
- Groups use the classic Join/Sync protocol. KIP-848 (`ConsumerGroupHeartbeat`) and static
  membership (`group.instance.id`) are not supported.
- In a cluster, a `transactional.id` is refused with `TRANSACTIONAL_ID_AUTHORIZATION_FAILED`;
  Kafka transactions work against a single node.
