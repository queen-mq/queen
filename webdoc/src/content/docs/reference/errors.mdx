A failed call answers a status code and a JSON body with a stable code. Branch on the code, never
on the message. This page lists every body shape, every code, and what a client does with it.
Rolled-back transactions are a 200, not an error: their `reason` values are on
[transaction](/reference/transaction/#rollback-reasons).

## Error bodies

| Where | Body | Branch on |
|---|---|---|
| Most routes: push, pop, ack, lease, queues, consumer groups, DLQ, status | `{"error": "<message>", "code": "<code>"}`, plus `"leader"` on a 503 `retry` when the leader is known | `code` |
| `POST /api/v1/transaction`, rolled back | `{"transactionId", "success": false, "reason", "error", "results": []}` | `reason` |
| `/api/v1/kv*` and `/api/v1/timers*` | `{"error": "<code>", "reason": "<finer code>", "detail": "<message>"}` | `error`, then `reason` |
| A pop refused for its parameters | `{"success": false, "error": "<message>", "messages": []}` | the status |
| Authentication and the tenancy header | `{"error": "<message>"}` | the status |
| The proxy | `{"error": "<message>", "code": "<code>"}` | `code` |

Every 429 and every 503 from the API carries `Retry-After`, in seconds. A 404 for a resource that
does not exist (a queue, a message) may carry only `error`.

## Engine codes

The `code` of the first shape.

| `code` | Status | Meaning | Client |
|---|---|---|---|
| `retry` | 503 | This node could not get the call to a leader: a leader change, no quorum lease, or the leader unreachable from the follower that forwarded it. | Retry after `Retry-After` (1 s). A write may have reached the leader, so it must be safe to repeat. |
| `no_leader` | 503 | No leader is known after the hold: an election is running, or a majority is down. | Retry. |
| `timeout` | 503 | The request deadline elapsed before an answer. A write may have committed. | Retry a write that is safe to repeat; otherwise read to check. |
| `outcome_unknown` | 503 | The leader changed while an ack, nack or DLQ move was being made durable, or a forwarded one was lost after it went out. It may or may not have applied. | Send the same ack again: since 2.0.0-beta.1 a repeat of an ack that applied is answered as the first one was. |
| `overloaded` | 429 | The node's admission budget for writes is full. | Retry after `Retry-After`. |
| `storage_full` | 507 | A node is above its disk high-water mark (`QUEEN_RAFT_DISK_HIGH_PCT`, 85%). Pushes, KV writes and timer schedules are refused; acks and deletes still work. | Free disk or add space. Retry later. |
| `name_too_long` | 413 | Tenant, queue and partition or group names together exceed the store's key budget. | Shorten the name the message names. |
| `bad_body` | 400 | The body is not the route's JSON shape. | Fix the request. |
| `bad_request` | 400 | A field is missing or invalid. | Fix the request. |
| any other code | 400 | The engine refused this request for the reason the message gives. | Fix the request. Do not retry it unchanged. |
| `no_such_route` | 404 | No route has that method and path. | Check the path against [the routes](/reference/http/#routes). |
| `internal` | 500 | A broker fault. | Report it. Do not retry in a loop. |
| `raft_phase1_unsupported` | 503 | The node does not serve this call. | Report it. |

**A 503 or a timeout on a write does not mean nothing happened.** Make writes safe to repeat
before you retry them: a deterministic `transactionId` on every pushed message, the same lease on
a repeated ack, a `required` marker in a transaction. See [dedup](/concepts/dedup/).

## After a leader change

- **Pushes, transactions, KV and timer calls** are logged under a request id. The node serving the
  call follows a leader change itself and resubmits under the same id until the deadline; one that
  committed is answered from its record. You get the normal answer, or 503 `timeout` if the
  deadline passes first.
- **Acks, nacks and DLQ moves** are answered from the leader's memory and made durable by its next
  checkpoint. If the leader changes while one is on its way to the log, or a forwarded one is lost
  after it went out, the answer is 503 `outcome_unknown`. Send the same ack, with the same lease,
  again.
- **Pops** are never in doubt. A claim nobody receives is handed back, or ends with its lease, and
  its messages are delivered again.
- **A follower that cannot reach the leader** answers 503 `retry` or `no_leader`. The request may
  have reached the leader first.

These hold for a cluster. Lease exclusivity across a leader change assumes node clocks within
`QUEEN_RAFT_MAX_CLOCK_SKEW_MS` (500 ms). See [guarantees](/concepts/guarantees/).

## KV and timers codes

The `error` of the third shape. The `reason` beside it is finer and stable too.

| `error` | Status | `reason`, and when | Client |
|---|---|---|---|
| `kv_bad_request` | 400 | A `kv_*` code: `kv_bad_namespace`, `kv_bad_key`, `kv_expiry_not_specified`, `kv_bad_ttl`, `kv_bad_expect`, `kv_unknown_op`, `kv_too_many_ops`, `kv_too_many_keys`, `kv_duplicate_key_in_call`, `kv_bad_body`. | Fix the request. |
| `timers_bad_request` | 400 | `timers_bad_body`, `timers_delay_required`, `timers_payload_required`, `timers_payload_not_base64`, `timers_too_many_ops`, or a server-owned field. | Fix the request. |
| `payload_too_large` | 413 | `kv_value_too_large`, `kv_key_too_large`, `timers_payload_too_large`, `timers_call_too_large`. | Shrink it, or raise the ceiling (see [limits](/reference/limits/)). |
| `timer_horizon_exceeded` | 403 | `timers_horizon`: `delayMs` is beyond the horizon in force. | Use a shorter delay. |
| `kv_quota_exceeded`, `timers_quota_exceeded` | 403 | The tenant is over its KV rows or bytes, or its timer count. Deletes and cancels are not refused for this. | Free space or raise the quota. Do not retry unchanged. |
| `feature_gated` | 403 | The tenant has no grant for this surface (`QUEEN_KV_REQUIRE_GRANT`). | An operator grants it. |
| `rate_limited` | 429 | The tenant's KV read or write rate. | Retry after `Retry-After`. |
| `kv_unavailable`, `timers_unavailable` | 503 | `kv_timeout`, `kv_retry`, `kv_no_leader`, `timers_timeout`, `timers_retry`, `no_leader`, or the node already tracks `QUEEN_KV_MAX_TENANTS` (10,000) tenants. | Retry after `Retry-After`. |
| `kv_disabled`, `timers_disabled` | 503 | An operator paused the surface at runtime. | Retry later. |
| `kv_error`, `timers_error` | 500 | A broker fault. | Report it. |

A lost precondition (`applied: false`) and a cancel of an absent timer (`ok: false`) are 200
answers, not errors.

## Authentication and tenancy

| Status | `error` | Client |
|---|---|---|
| 401 | `Authentication required`, `Token has expired`, `Invalid token signature`, `Invalid token issuer`, `Invalid token audience`, `Unknown key ID`, ... | Get a new token. |
| 403 | `Insufficient permissions` | Use a token whose role covers the route's access level ([HTTP API](/reference/http/#authentication)). |
| 400 | `invalid x-queen-tenant header (must be a UUID)` | Fix the proxy that sets the header. |

## Proxy codes

Behind the proxy, these come before the request reaches the broker. Limits and plans are on
[tenants](/operate/tenants/).

| `code` | Status | Meaning |
|---|---|---|
| `unauthorized` | 401 | No valid API key or session. |
| `forbidden` | 403 | The credential has no role on this cluster, or is for another cluster. |
| `rate_limited` | 429 | Request or message rate limit; `Retry-After` set. |
| `quota_exceeded` | 403 | A queue, partition or monthly message quota is reached. |
| `storage_quota_exceeded` | 403 | The retained-bytes quota is reached; pushes are blocked. |
| `push_blocked` | 403 | Pushes are blocked on this cluster (billing hold). |
| `cluster_suspended` | 403 | The cluster is suspended. |
| `feature_gated` | 403 | The route is not in the plan. |
| `route_blocked` | 404 | An operator-only broker route, not served to tenants. |
| `cluster_unknown` | 421, 404 | The `Host` names no cluster. |
| `payload_too_large` | 413 | The body is over the edge limit. |
| `bad_gateway`, `upstream_timeout` | 502, 504 | The broker did not answer. |

## What the JS client does

- Retries a 5xx or a network error. With one URL it makes up to three attempts, waiting 1 s, then
  2 s; with several URLs and failover on, it tries each URL once. It treats every 5xx alike, including 507 and 503
  `outcome_unknown`.
- Retries a 429 after `Retry-After`, up to 10 attempts (a long-poll pop: without limit).
- Throws any other 4xx at once, with `error.status` and `error.code` from the body.
- Returns a transaction rolled back by a lost `required` precondition, and throws every other
  rollback with `error.reason`.
