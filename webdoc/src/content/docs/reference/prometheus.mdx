`GET /metrics/prometheus` returns exposition text with content type
`text/plain; version=0.0.4`. Every family carries `# HELP` and `# TYPE`.

`GET /metrics` is a different endpoint and is **not** Prometheus text: it returns
a small JSON object with uptime, aggregate request and message counts, resident
memory, `"engine":"raft"` and a `raft` block (the node's role, whether a leader
is known, term, applied and committed index, lag, `storageReady`). Scraping it
will fail to parse.

## The endpoint cannot be protected by broker authentication

`/health`, `/metrics` and `/metrics/prometheus` resolve to access level
`public` in the broker's route table, and the authentication middleware
short-circuits on `public` before it ever looks for a token. They are also in
the default `JWT_SKIP_PATHS`. Removing them from that list changes nothing,
because the level check wins.

<Aside type="danger">
Turning on `JWT_ENABLED` does not close this endpoint. If the broker's port is
reachable, so is every number below. Restrict it at the network layer: a
reverse proxy, a NetworkPolicy, or a listener that is not routable from tenant
traffic.
</Aside>

The embedded proxy (`QUEEN_PROXY_EMBEDDED=true`) changes this on the port it
serves. There, `/metrics` and `/metrics/prometheus` answer only a request that
carries the control-plane token (`x-queen-cp-token`, or
`Authorization: Bearer <token>`, set with `QUEEN_PROXY_CP_TOKEN`); every other
request gets `404`, and so does every request when no token is configured.
With `QUEEN_PROXY_PORT` set to a port other than `PORT`, `PORT` serves the
broker router directly and the rule above applies there: keep that port
internal and scrape it from inside the network.

## Every series is node-local

Each node of a cluster reports what it measured itself. The counters live in
memory and reset to zero when the process restarts; the raft index and storage
gauges describe this node's own log and data directory. There is no cluster-wide
lifetime total and no per-queue minute rate: scrape every node and aggregate in
Prometheus.

The raft indexes are the one place where comparing nodes is the point: a
follower's applied index trailing the leader's committed index is replication
lag.

## How a scrape is assembled

The response is built in one pass from memory and the node's own store, in a
fixed order, with no call to another node:

1. The broker's in-process families: `queen_uptime_seconds`,
   `queen_process_resident_memory_bytes`, the `queen_process_*` request and
   message counters, `queen_parked_long_polls`, and the key/value and ephemeral
   families.
2. The pipeline timing families (`queen_raft_*_seconds` and friends), emitted
   only while `QUEEN_RAFT_METRICS` is on, which is the default. With it off,
   nothing is recorded and the whole block is skipped rather than rendered as
   zeros.
3. The state-machine families of this node: store operations and map use,
   raft indexes, entries in flight, proposals, queue-log files and bytes, and
   the disk gate.

## The state-machine families

| Family | Type | Labels | What it says |
| --- | --- | --- | --- |
| `queen_raft_index` | gauge | `kind` = `log`, `committed`, `applied` or `durable` | The node's positions in the replicated log. |
| `queen_raft_inflight` | gauge | none | Entries committed or proposed but not yet applied. |
| `queen_raft_proposals_total` | counter | none | Proposals accepted since the node opened its store. |
| `queen_raft_log_storage` | gauge | `kind` = `files` or `bytes` | The queue-log files on this node's data directory. |
| `queen_raft_storage_full` | gauge | none | `1` while the disk gate refuses writes that grow storage, else `0`. |
| `queen_raft_store_operations_total` | counter | `kind` | Operations on the embedded store, by kind. |
| `queen_raft_store_map_bytes` | gauge | `kind` = `capacity` or `used` | The store's memory map: its size and how much of it is used. |
| `queen_raft_store_ram_rows` | gauge | `ks`, `kind` = `live` or `dirty` | Rows per in-memory keyspace, and the keys changed since the last checkpoint. |
| `queen_raft_store_readers` | gauge | `kind` = `used` or `limit` | Reader slots of the embedded store. |

`queen_raft_storage_full` turns to `1` when the data directory's filesystem
reaches `QUEEN_RAFT_DISK_HIGH_PCT` percent used (default 85), or the store's map
reaches 85 percent used, and back to `0` below `QUEEN_RAFT_DISK_LOW_PCT`
(default 80) and 80 percent of the map. While it is `1`, pushes answer `507`. It
is the first alert to write.

With `QUEEN_RAFT_GROUPS` above 1 the node runs several raft groups, and every
line of this block carries a `group` label naming the group it describes. With
the default of one group there is no `group` label.

## The timing families

The pipeline timing families are Prometheus summaries: each sample line carries
`quantile` = `0.5`, `0.9`, `0.99`, `0.999` or `1` (the maximum), followed by
`_count` and `_sum`. They are cumulative since the process started, and a
quantile is the upper bound of the histogram bucket it falls in, so read it as
"at most". The per-command planning family,
`queen_raft_planner_plan_seconds`, carries `kind` next to `quantile`. These
families are process-wide: with several raft groups they have no `group` label.

## Per-queue series are not tenant-scoped

No per-queue series carries a tenant label. When `QUEEN_TENANCY_HEADER` is on
and two tenants hold the same queue name, their series collide:
`queen_parked_long_polls` sums the per-tenant gauges into one line per queue
name.

<Aside type="danger">
`/metrics/prometheus` is a cell-wide operator surface. Exposing it to a tenant
leaks other tenants' queue names and volumes. The proxy classifies it as an
operator route for exactly this reason.
</Aside>

## The rule about the `tenant` label

> The `tenant` label is allowed **only** on occupancy gauges, where it is one
> series per tenant written by a background job and bounded by the control
> plane. It is **forbidden** on per-operation counters, where it would be tenant
> times operation times outcome, that is, a cardinality chosen by whoever calls
> the API.

The key/value routes are the first surface in this product whose call rate is
decided by somebody else's web traffic, so they are the first place that rule
could really have been broken. The per-tenant view of a hot path lives in the
broker's top-N log lines and in the JSON status endpoint, not here.

`queen_kv_read_rejected_total{reason="rate_limited"}` becoming non-zero is worth
a panel even though it is not a fault. It is the earliest warning of a customer
who has just put key/value reads on their own end users' request path. The
`reason` label is read from the verdict rather than from the status code, so
`disabled` means the operator's runtime kill switch and nothing else.

## No depth families

There is no per-queue depth family and no dead-letter depth family. Depth under
a delivery policy is a per-**group** number, not a per-queue one, and a
conflating group's remaining work is not the queue's message count. Ask
[`GET /api/v1/resources/queues/:queue/depth`](/reference/http/queues#get-apiv1resourcesqueuesqueuedepth)
for it, per group, and use the consumer-group lag endpoints and
`GET /api/v1/dlq` for backlog and dead letters.
