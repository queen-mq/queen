This is the complete surface of the broker binary, on its own page so it is linkable and
searchable. It is not maintained by hand: it is generated from the source, and each route's
required access level is resolved through `route_access_level` in `server/src/auth.rs`. A route
that does not exist in the code cannot appear here, and one that is added appears without anyone
editing this page.

The broker serves routes in two ways. The message plane (push, pop, ack, transaction, lease
extension), the KV, timer and ephemeral verbs, the operational endpoints, the Raft membership
routes and the dashboard identity routes are registered on the router in
`server/src/handlers/raft.rs`. Every other `/api/` and `/streams/` path falls through to the state
machine's generic adapter, whose dispatch table is `api_impl` in
`server/src/rsm/facade/real/phase2.rs`; a path it does not know answers a JSON `404`.

How to read the columns:

- **Access level**: the role set that satisfies the route. The levels are not a ladder;
  `write-only` and `read-only` are disjoint capabilities. The
  [conventions page](/reference/http) has the matrix, and the levels apply only when
  `JWT_ENABLED` is on.
- **Tenant-scoped**: whether the handler resolves a tenant identity and hands it to the state
  machine. With native tenant scoping off (the default) every request resolves to one default
  tenant, and this column tells you which handlers would participate if it were on. Routes
  marked `no` are cell-wide reads or operator surfaces; that matters for multi-tenant
  deployments, covered in [Self-hosting](/deploy/).
- **Dashboard identity (broker-direct)** is the small `/auth` surface the broker answers when
  it serves the dashboard itself. The routes are `public` by design; `/auth/me` enforces the
  auth state in its own handler. [The dashboard page](/deploy/dashboard/) explains the
  standalone identity it returns.

The five message-plane routes have a page each documenting their request and response
fields: [push](/reference/http/push), [pop](/reference/http/pop),
[ack](/reference/http/ack), [transaction](/reference/http/transaction) and
[lease extension](/reference/http/lease). The stream-processing surface has one too:
[streams](/reference/http/streams) documents the three `/streams/v1` routes field by
field, because that protocol is public and versioned rather than an SDK internal. The
remaining groups are documented on the other pages of this section.
