`queenctl` is a single static binary over the HTTP API, built on the Go SDK. Use it to push and
tail messages, inspect queues, partitions, consumer groups and the DLQ, rewind a group, and apply
queue manifests.

## Install

- **Pre-built:** each `clients/client-cli/vX.Y.Z` tag publishes archives on the
  [queen-mq/queen GitHub Releases](https://github.com/queen-mq/queen/releases), named
  `queenctl_<version>_<os>_<arch>`: `linux` and `macos` on `x86_64` and `arm64`, `windows` on
  `x86_64` (a `.zip`).
- **Go 1.24 or later:**

  ```bash
  go install github.com/smartpricing/queen/clients/client-cli/cmd/queenctl@latest
  ```

- **From source:**

  ```bash
  cd clients/client-cli && make build    # ./bin/queenctl
  ```

## Connect

```bash
queenctl config set-context local --server http://localhost:6632
queenctl ping
```

Contexts live in `~/.queen/config.yaml` (`--config` moves it); the first one you create becomes the
current one. A setting is taken from, lowest to highest: the file's `current-context`,
`$QUEEN_CONTEXT`, `--context`, then `$QUEEN_SERVER` / `$QUEEN_TOKEN`, then `--server` / `--token`.

| Credential | Command |
|---|---|
| A JWT or a proxy API key (`qk_...`) | `queenctl login --method token` |
| Email and password on the proxy | `queenctl login --method password -u you@example.com` |
| Google or GitHub through the proxy | `queenctl login --method google` (or `github`) |

A token is stored in the OS keychain; `config set-context --no-keychain` keeps it in the file
instead, and `--token-ref env` reads `$QUEEN_TOKEN` at run time. For CI, use an API key: it does
not expire.

## Commands

| Group | Commands |
|---|---|
| Data | `push`, `pop`, `tail`, `ack`, `tx -f`, `lease extend` |
| Queues | `queue list\|describe\|configure\|delete\|depth\|stats`, `partition list\|describe\|seek`, `namespace list`, `task list`, `apply -f` |
| Consumer groups | `cg list\|describe\|lag\|seek\|delete\|refresh-stats`, `lag`, `replay` |
| Messages and DLQ | `messages list\|get\|delete\|traces`, `dlq list\|describe\|retry\|drain`, `traces names\|by-name\|by-message` |
| Ephemeral queues | `ephemeral push\|pop\|ack\|configure\|reset\|delete\|queues\|depth` |
| Node | `ping`, `version`, `status`, `metrics [--prometheus]`, `analytics overview\|queue-lag\|queue-ops\|queue-parked\|retention\|system\|worker`, `bench` |
| Plumbing | `config view\|current-context\|get-contexts\|set-context\|use-context\|delete-context`, `login`, `logout`, `completion`, `docs` |

`queenctl <command> --help` lists every flag. Commands that remove data (`queue delete`,
`cg delete`, `messages delete`, `dlq retry`, `dlq drain`, `ephemeral reset|delete`) refuse to run
without `--yes`. `push`, `tx`, `apply`, `replay`, `cg seek`, `dlq retry` and `dlq drain` take
`--dry-run`.

## Examples

```bash
# Push NDJSON, one partition per user, 500 messages per request
cat events.ndjson | queenctl push events --batch 500 --partition-key user_id

# Follow a queue as consumer group "debug" (tail acks what it prints for that group)
queenctl tail orders --cg debug --follow | jq '.data'

# Rewind a consumer group fifteen minutes, then check its lag
queenctl replay orders --cg analyzer --to '15m ago'
queenctl lag --min-seconds 30

# Look at the dead letters of a queue and put one back
queenctl dlq list --queue orders
queenctl dlq retry <partitionId> <transactionId> --yes

# Declare a queue and a consumer group
cat <<EOF | queenctl apply -f -
kind: Queue
name: orders
config:
  leaseTime: 60
  retryLimit: 5
---
kind: ConsumerGroup
name: analyzer
queue: orders
seek-to: beginning
EOF
```

A manifest is the whole configuration of its queue: an option it leaves out goes back to its
default. `queue configure --flag` changes only the flags you pass.

## Output and exit codes

Output is a table on a terminal and JSON in a pipe; `-o table|wide|json|ndjson|yaml|jsonpath=<expr>`
overrides it. `tail` always writes NDJSON.

| Exit code | Meaning |
|---|---|
| 0 | Success |
| 1 | User error: a bad flag, input or argument |
| 2 | Server error, or the server is unreachable |
| 3 | Authentication or authorization failure |
| 4 | Success with nothing to do: an empty pop, no dead letters |

## Limits

- There is no `kv` or `timer` command. Use `curl` against `/api/v1/kv` and `/api/v1/timers`, or an
  SDK.
- `tx -f` sends only ack and push operations. It does not forward `requiredLeases`, a `leaseId` or
  the items' `transactionId`, so its acks are not fenced and a retried push is not deduplicated.
  For a fenced, idempotent transaction, use the [HTTP API](/reference/transaction/) or an SDK.
- Through the proxy, routes that cannot be scoped to one tenant answer 404: `status` without a
  queue, `metrics`, `analytics system|worker`, `cg refresh-stats`, and `pop --namespace/--task`
  without a queue. They work against a node directly.
