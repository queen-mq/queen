QueenMQ speaks JSON over HTTP on port 6632, so every client is a thin layer over the same routes, and `curl` is a complete client. An SDK adds the parts that are tedious by hand: consume loops that ack for you, lease renewal, push buffering, retries with failover across the nodes of a cluster, and builders for transactions, KV, timers and locks.

<Why>the logic lives in the broker, so a client has little to get wrong, and a seventh language is a few hundred lines of HTTP calls.</Why>

## Install and connect

<Tabs>
<TabItem label="JavaScript">

```bash
npm install queen-mq
```

```js
import { Queen } from 'queen-mq'

const queen = new Queen({ url: 'http://localhost:6632' })
// ...
await queen.close()
```

Node.js 24 or later. With `urls: [...]` instead of `url`, the client sends each consumer's pops to
the node that a consistent hash of its queue, partition and group picks (the default `affinity`
strategy; `round-robin` and `session` are the others), and fails over to another node on a network
error or a 5xx.
[README](https://github.com/queen-mq/queen/tree/master/clients/client-js)

</TabItem>
<TabItem label="Python">

```bash
pip install queen-mq
```

```python
from queen import Queen

async def main():
    queen = Queen(url="http://localhost:6632")
    # ... every call is awaited
    await queen.close()
```

Python 3.9 or later. The client is asyncio from end to end, and `url` is a keyword argument.
[README](https://github.com/queen-mq/queen/tree/master/clients/client-py)

</TabItem>
<TabItem label="Go">

```bash
go get github.com/smartpricing/queen/clients/client-go/v2
```

```go
import queen "github.com/smartpricing/queen/clients/client-go/v2"

client, err := queen.New("http://localhost:6632")
if err != nil {
	return err
}
defer client.Close(context.Background())
```

Go 1.24 or later. `queen.New` also takes a slice of URLs or a `ClientConfig`. The repository
lives at `github.com/queen-mq/queen`, but the module path still carries the organization it
started in, so import it exactly as written above.
[README](https://github.com/queen-mq/queen/tree/master/clients/client-go)

</TabItem>
<TabItem label="Rust">

```bash
cargo add queen-mq serde_json
cargo add tokio --features rt-multi-thread,macros
```

```rust
use queen_mq::{Config, Queen};

let queen = Queen::connect(Config::new("http://localhost:6632"))?;
```

Rust 1.86 or later, on tokio. `connect` checks the configuration and opens no socket; the first
request does.
[README](https://github.com/queen-mq/queen/tree/master/clients/client-rust)

</TabItem>
<TabItem label="C++">

The client is one header, `clients/client-cpp/queen_client.hpp`, used from a checkout of the
repository: it includes the thread pool in `clients/server/include/` by a relative path, and
`clients/server/vendor/` carries the nlohmann/json it needs. You install cpp-httplib 0.27.0 or later and OpenSSL
(`brew install cpp-httplib openssl` on macOS).

```cpp
#include "queen_client.hpp"

queen::QueenClient client("http://localhost:6632");
// ...
client.close();
```

```bash
g++ -std=c++17 -O2 -pthread \
    -I clients/client-cpp -I clients/server/vendor \
    -I /opt/homebrew/include -I "$(brew --prefix openssl)/include" \
    app.cpp -o app \
    -L "$(brew --prefix openssl)/lib" -lssl -lcrypto -lpthread
```

C++17 or later. Link OpenSSL even over plain HTTP: the header turns on cpp-httplib's TLS support
itself. Fluent consumers can enable dashboard observations with
`.supervision(queen::SupervisionConfig{"billing-production"})` before `.consume(...)`;
they are off by default. The README describes worker counts, handler progress and publication
timings. These observations do not restart or scale application processes.
[README](https://github.com/queen-mq/queen/tree/master/clients/client-cpp)

</TabItem>
<TabItem label="PHP and Laravel">

```bash
composer require queen-mq/php-client
```


PHP 8.3 or later. The same package carries the Laravel integration: package discovery registers a

The six clients are at 2.6.0 and talk to any 2.x broker. Locks need a 2.1 broker, and the binary forms a 2.3 one.

## How each SDK names things

These pages name options and methods as the JavaScript client spells them. The others follow the habits of their language:

| JavaScript | Python | Go | Rust | PHP | C++ |
| --- | --- | --- | --- | --- | --- |
| `leaseTime` | `lease_time` | `LeaseTime` | `lease_time` | `leaseTime` | `lease_time` |
| `subscriptionMode('all')` | `subscription_mode("all")` | `SubscriptionMode(queen.SubscriptionModeAll)` | `subscription_mode(SubscriptionMode::All)` | `subscriptionMode('all')` | `subscription_mode("all")` |
| `idleMillis(1500)` | `idle_millis(1500)` | `IdleMillis(1500)` | `idle_millis(1500)` | `idleMillis(1500)` | `idle_millis(1500)` |
| `ttl: '30d'` | `ttl=timedelta(days=30)` | a `time.Duration` | a `Duration` | `ttlSeconds` | `KvTtl` |
| `await` on every call | `await` (asyncio) | `ctx` on every call | `.await` (tokio) | blocking | blocking |

## Where the SDKs differ

The core is the same everywhere: push, pop, consume, ack, transactions, KV, timers and locks. These are the differences the programs behind these pages ran into, on 2.6.0:

| Topic | JavaScript | The others |
| --- | --- | --- |
| Streams | Yes | Python, Go and Rust too. PHP and C++ have none. |
| Consumer callbacks (`onSuccess`, `onError`) | Yes | Python and PHP too. Go, Rust and C++ ack in the handler. |
| A refused message in a push | Throws | Returned as that message's status. |
| A batch ack with mixed statuses | One call | Python and PHP too. Go, Rust and C++: one call per status, or a transaction of acks. |
| Stopping a consume loop | At once; unstarted messages go back with `retry` | After the current message; the rest wait for their lease. |
| zstd for the binary forms | Built in | Python 3.14 or `queen-mq[zstd]`, PHP `ext-zstd`, C++ `-lzstd`; Go and Rust built in. |

Where an SDK lacks a method, the route is still there over HTTP: the C++ code on these pages calls a few routes directly, and says why in a comment.

## curl and queenctl

Every SDK call is one of the broker's routes, so anything that can send an HTTP request is a client:

```bash
curl -s -X POST http://localhost:6632/api/v1/push -H 'content-type: application/json' \
  -d '{"items":[{"queue":"orders","partition":"customer-123","payload":{"orderId":8891}}]}'
```

The [HTTP reference](/reference/http/) lists every route. `queenctl`, the operator CLI (status, tail, push, replay, lag, dead letters), ships inside the Docker image (`docker exec queen queenctl status`) and as release binaries. See [queenctl](/reference/queenctl/).

## Binary forms, by SDK

The three options of [binary push, compression and framed pop](/writing-applications/push/#binary-push-compression-and-framed-pop) are spelled:

| Client | Options |
| --- | --- |
| JavaScript | `binaryPush`, `pushCompression`, `framedPop` in the `Queen` config |
| Python | `binary_push`, `push_compression`, `framed_pop`, keyword arguments of `Queen` |
| Go | `BinaryPush`, `PushCompression`, `FramedPop` in `ClientConfig` |
| Rust | `.binary_push(true)`, `.push_compression(true)`, `.framed_pop(true)` on `Config` |
| C++ | `binary_push`, `push_compression`, `framed_pop` in `ClientConfig` |
| PHP | `binaryPush`, `pushCompression`, `framedPop` in the `Queen` config; under Laravel `binary_push`, `push_compression`, `framed_pop` in `config/queen.php` |

## Reads by offset, by SDK

[`fetch`](/writing-applications/pop/#read-it-again) reads a partition by position, and `changedSince` lists the partitions written since a time. Neither takes a lease or moves a cursor.

| Client | Read | Discover |
| --- | --- | --- |
| JavaScript | `queue(q).fetch(partitions, { offsets, maxBytes })` | `queue(q).changedSince(since)` |
| Python | `queue(q).fetch(partitions, offsets=..., max_bytes=...)` | `queue(q).changed_since(since)` |
| Go | `Queue(q).Fetch(ctx, partitions, FetchOptions{...})` | `Queue(q).ChangedSince(ctx, since)` |
| Rust | `queue(q).fetch(partitions)`, `fetch_with(partitions, FetchOptions)` | `queue(q).changed_since(since)` |
| C++ | `queue(q).fetch(partitions, FetchOptions)` | `queue(q).changed_since(since)` |
| PHP | `queue($q)->fetch($partitions, $offsets, $maxBytes)` | `queue($q)->changedSince($since)` |

`changedSince` answers a `safeTime`: give it as the next `since` to see only what changed after this call. It is the broker's time, so never compare it with your own clock.

## Consumer supervision

Every SDK can report what its consumers are doing (workers, handler progress) to the dashboard, through the KV API. It is off by default; turn it on per consume loop with `.supervision({ group: 'billing-production' })`, spelled as above in each language. Each run of a loop is one instance with fresh counters, published every 10 seconds (PHP: when the loop gets control back). The [status contract](/reference/supervisor-status/) defines what is published.

<Why>a dashboard that shows which workers are alive and what they are doing saves a lot of log reading. It stays off by default because it writes to KV.</Why>

## The broker inside a Rust program

A Rust program can run the broker in its own process, as the library `queen::Broker`. Every call
goes through the same handler functions the HTTP router dispatches to, so behaviour and defaults are
the broker's, and the data lives in a directory on local disk that you name.

2.0 is not on crates.io yet (the `queen-engine` published there is 1.3, which ran on PostgreSQL),
so depend on the repository, pinned to the 2.0.0 commit:

```toml
[dependencies]
queen-engine = { git = "https://github.com/queen-mq/queen", rev = "86562c25d", default-features = false }
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
serde_json = "1"
```

The crate imports as `queen` and needs Rust 1.88. `default-features = false` leaves out what only
the standalone binary needs: the HTTP listener, the dashboard, the embedded proxy and the Kafka
facade. Start it on a data directory:

The embedded broker is one node and one tenant. It exposes push, pop, ack, lease renewal,
transactions, queue configuration, the dead-letter queue and ephemeral queues. KV and timers are
reachable only inside a transaction, so there is no standalone KV read or timer listing, and
consumer-group administration, queue listings, traces and streams are not exposed. A panic in one
of the broker's core threads (planner, log writer, apply, checkpoint, raft) aborts the process, and
the next start replays from the data directory; any other panic, your own included, unwinds as
usual. Never open one data directory from two brokers at once.
