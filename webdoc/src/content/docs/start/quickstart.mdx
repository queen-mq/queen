Docker and five minutes. At the end you have a broker and one message that went in and came out.
There is no database to run, no schema to migrate and no extension to install: the broker keeps
its state in a directory on its own disk.

## Start a broker

<Steps>

1. **The broker.** It listens on `PORT`, default `6632`, and keeps everything in `QUEEN_RAFT_DIR`,
   default `/var/lib/queen/raft`. The volume is what keeps your messages when the container is
   replaced.

   ```bash
   docker run -d --name queen -p 6632:6632 -v queen-data:/var/lib/queen/raft ghcr.io/queen-mq/queen:latest
   ```

2. **Check it.** `/health` answers `200` once the node knows a leader, which a single node does as
   soon as it has opened its data directory.

   ```bash
   curl -s http://localhost:6632/health
   ```

   The answer carries `"status":"healthy"`, `"engine":"raft"`, the version, and a `raft` object
   whose `role` is `leader`. An empty answer on the first try means the broker is still opening
   its data directory: run it again a second later. If it stays empty, `docker logs queen` says why.

</Steps>

The same binary serves its dashboard on the same port: open `http://localhost:6632`.

## Push and consume

Nothing to create first: the queue and the partition are provisioned by the first push that names
them. The only decision is the partition key, the thing whose events must stay in order.

<Tabs>

const client = new Queen('http://localhost:6632')

<TabItem label="curl">

```bash
curl -i -X POST http://localhost:6632/api/v1/push -H 'Content-Type: application/json' -d '{"items":[{"queue":"orders","partition":"customer-42","payload":{"hello":"world"}}]}'
```

```json
[{"index":0,"message_id":"019842f1-...","transaction_id":"019842f1-...","queueName":"orders","status":"queued"}]
```

Each item also carries the message's `offset` in its partition.

```bash
curl -i "http://localhost:6632/api/v1/pop/queue/orders?batch=1&wait=true&consumerGroup=demo&subscriptionMode=all"
```

That pop took a **lease**: the span belongs to this group until you acknowledge it or the lease
expires. Acknowledge with the `transactionId` and `partitionId` from the message, plus the
`leaseId`:

```bash
curl -i -X POST http://localhost:6632/api/v1/ack -H 'Content-Type: application/json' -d '{"transactionId":"019842f1-...","partitionId":"6b1c...","status":"completed","consumerGroup":"demo","leaseId":"019842f1-..."}'
```

An empty pop answers `204` with no body at all, so branch on the status code before parsing.
The wire format is in [the HTTP reference](/reference/http).

</TabItem>
</Tabs>

## Two things worth doing before you move on

- **Push twice with the same `transactionId`.** The second returns `status: "duplicate"` and the
  first message's id, having written nothing.
- **Pop with a second consumer group.** It gets the same message again, from its own cursor.
  Groups are fan-out.

## Clean up

```bash
docker rm -f queen && docker volume rm queen-data
```
