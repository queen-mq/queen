Every Queen client speaks the same API: JSON over HTTP/1.1, on port `6632`. Pick the SDK for your
language, call the routes with curl, or run the broker inside a Rust process. The connect lines
below are the ones the tutorials in `examples/tutorials/` run.

## Install and connect

<Tabs>
<TabItem label="JavaScript">

```bash
npm install queen-mq
```

```js
import { Queen } from 'queen-mq'

const queen = new Queen({ url: 'http://localhost:6632' })
// ...
await queen.close()
```

Node.js 24 or later. `urls: [...]` instead of `url` spreads requests over several nodes.
[README](https://github.com/queen-mq/queen/tree/master/clients/client-js)

</TabItem>
<TabItem label="Python">

```bash
pip install queen-mq
```

```python
from queen import Queen

async def main():
    queen = Queen(url="http://localhost:6632")
    # ... every call is awaited
    await queen.close()
```

Python 3.9 or later. The client is asyncio throughout.
[README](https://github.com/queen-mq/queen/tree/master/clients/client-py)

</TabItem>
<TabItem label="Go">

```bash
go get github.com/smartpricing/queen/clients/client-go
```

```go
import queen "github.com/smartpricing/queen/clients/client-go"

client, err := queen.New("http://localhost:6632")
if err != nil {
	return err
}
defer client.Close(context.Background())
```

`queen.New` also takes a slice of URLs or a `ClientConfig`. The module path is
`github.com/smartpricing/queen/clients/client-go`.
[README](https://github.com/queen-mq/queen/tree/master/clients/client-go)

</TabItem>
<TabItem label="Rust">

```bash
cargo add queen-mq serde_json
cargo add tokio --features rt-multi-thread,macros
```

```rust
use queen_mq::{Config, Queen};

let queen = Queen::connect(Config::new("http://localhost:6632"))?;
```

Rust 1.86 or later, on tokio. `connect` validates the configuration and opens no socket; the
first request does. [README](https://github.com/queen-mq/queen/tree/master/clients/client-rust)

</TabItem>
<TabItem label="C++">

The client is one header, `clients/client-cpp/queen_client.hpp`. Copy it into your include path
with its dependencies: cpp-httplib, nlohmann/json and OpenSSL.

```cpp
#include "queen_client.hpp"

queen::QueenClient client("http://localhost:6632");
// ...
client.close();
```

C++17 or later. Link with `-lssl -lcrypto -lpthread`, even over plain HTTP: the header turns on
cpp-httplib's TLS support unconditionally.
[README](https://github.com/queen-mq/queen/tree/master/clients/client-cpp)

</TabItem>
<TabItem label="PHP and Laravel">

```bash
composer require queen-mq/php-client
```

```php
use Queen\Queen;

$queen = new Queen('http://localhost:6632');
```

PHP 8.3 or later. In a Laravel application, package discovery registers a `queen` queue
connection, and your jobs stay ordinary Laravel jobs:

```dotenv
QUEUE_CONNECTION=queen
QUEEN_URL=http://127.0.0.1:6632
```

See [Laravel](/guides/laravel/).
[README](https://github.com/queen-mq/queen/tree/master/clients/client-php)

</TabItem>

## curl is a client

Every SDK is a wrapper over the same routes, so anything that can send an HTTP request is a full
client: push, pop, ack, `POST /api/v1/transaction`, KV and timers. Nothing to install.

```bash
curl -s -X POST http://localhost:6632/api/v1/push -H 'content-type: application/json' \
  -d '{"items":[{"queue":"orders","partition":"customer-123","payload":{"orderId":8891}}]}'
```

What the SDKs add is convenience built from those routes, such as client-side push buffering,
consume loops and `once`. The [quickstart](/start/quickstart/) runs a whole step with curl and jq,
and [the HTTP reference](/reference/http/) lists every route.

`queenctl`, the operator CLI (tail, push, replay, lag, dead letters), ships in the Docker image and
as release binaries. See [queenctl](/reference/queenctl/).

## The embedded Rust broker

A Rust program can run the broker in its own process, as the library `queen::Broker`. Every call
goes through the same handlers the HTTP broker dispatches to, so behaviour and defaults are the
broker's. It runs a single node, with its data directory on local disk.

```toml
[dependencies]
queen-engine = { version = "2.0.0-beta.3", default-features = false }
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
serde_json = "1"
```

The crate is `queen-engine` and imports as `queen`; it needs Rust 1.88. `default-features = false`
leaves out the HTTP listener, the dashboard, the proxy and the Kafka facade, which only the
standalone binary needs.

## Limits

- **The SDKs do not all stop in the same place.** The table above lists every row where one
  diverges. Where an SDK lacks a method, the route is still there over HTTP.
- **Embedded is one node and one tenant.** Its documented scope is a single node; a cluster is the
  standalone binary. Never open one data directory from two brokers at once.
- **Embedded leaves some surfaces out:** consumer-group administration, queue listings, traces
  and streams. The dead-letter queue is covered.
- **A panic in a core thread of the embedded broker aborts the process** (planner, log writer,
  apply, checkpoint, raft). The next start replays from the data directory. Panics elsewhere,
  including your own, unwind as usual.
