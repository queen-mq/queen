Acknowledging a message does not delete it. Consumption is a cursor per consumer group and the
messages stay until retention removes them, so backfilling a new consumer, reprocessing after a
bug and auditing what was delivered all happen without asking the producer to send anything twice.

Two routes do it, and neither touches a message. `subscriptionMode` on the pop seeds a cursor that
does not exist yet, which is how a group created today reads events from last week.
`POST /api/v1/consumer-groups/<group>/queues/<queue>/seek` moves a cursor that already exists,
which is the only way to rewind a group: the mode is read once, at creation, and ignored on every
pop after it.

The seek body is either `{"toEnd": true}` or a timestamp, and a body carrying neither is a `400`.
Resolution is segment-granular rather than per-message, so the cursor lands just before the first
segment created at or after the timestamp. The seek also releases any live lease, so an in-flight
batch is abandoned rather than acknowledged.

## Run it

Against a broker from [the quickstart](/start/quickstart), with `curl` and `jq` on the path:

```bash
QUEEN_URL=http://localhost:6632 bash examples/tutorials/http/04-replay.sh
```

The script checks its own outcome and exits non-zero if a check fails. Every tutorial in this
section runs in the repository's own suite: `examples/tutorials/run.sh http`.
