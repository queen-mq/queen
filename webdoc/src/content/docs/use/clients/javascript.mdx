The JavaScript client is the reference implementation: every other SDK is a transliteration
of it. ESM-only, Node 22 or newer, broker client and streaming SDK in one package.

<PackageManagers pkg="queen-mq" />

```js
import { Queen } from 'queen-mq'

const client = new Queen('http://localhost:6632')
```

It also exports `Admin`, the defaults objects and the streaming entry points as named ESM
exports; the full list is in [Reference](/reference/sdk/javascript).

## Construct a client

```js
const client = new Queen({
  urls: ['http://broker-a:6632', 'http://broker-b:6632'],
  bearerToken: process.env.QUEEN_TOKEN,
  timeoutMillis: 30000,
  loadBalancingStrategy: 'affinity',
  handleSignals: false,
})
```

The constructor accepts a URL string, an array, or a config object; no `url`/`urls` throws.
One URL is a direct client; more build a load balancer with failover: `5xx` and network
errors move to the next backend, `4xx` never retries across backends, `429` retries in place
(see [429 and 403](#429-and-403)).

### Client options

Defaults come from `CLIENT_DEFAULTS` in `utils/defaults.js`.

| Option | Default | What it does |
| --- | --- | --- |
| `url` / `urls` | n/a | Required. One backend or many. |
| `timeoutMillis` | `30000` | Per-request timeout. A long-poll pop adds 5 s of slack on top so the server-side timeout always fires first. |
| `retryAttempts` | `3` | **Total** tries for `5xx` and network failures, with exponential backoff from `retryDelayMillis`. |
| `retryDelayMillis` | `1000` | First retry delay; doubles per attempt. |
| `loadBalancingStrategy` | `'affinity'` | `'round-robin'`, `'session'` or `'affinity'`. Affinity hashes the pop's `queue:partition:consumerGroup` key onto a ring so the same lane keeps hitting the same broker. |
| `affinityHashRing` | `128` | Virtual nodes per backend on the affinity ring. |
| `enableFailover` | `true` | Try the next backend on `5xx` / network error. |
| `healthRetryAfterMillis` | `5000` | How long a backend stays marked unhealthy. |
| `bearerToken` | `null` | Sent as `Authorization: Bearer <token>` on every request. |
| `headers` | `{}` | Extra headers on every request. |
| `hostHeader` | `null` | Advertise a different `Host` than the address dialed. |
| `handleSignals` | `true` | Register `SIGINT` / `SIGTERM` handlers that flush and exit. |
| `logger` | `null` | Any object with `info`/`warn`/`error`. |
| `structuredLogs` | `false` | Call the logger pino/bunyan style: `info(fields, message)`. |
| `retry429` | n/a | `{ maxAttempts, baseMs, capMs }`. See below. |

<Aside type="note">
**`headers: { Host }` cannot work**: `fetch` drops it silently, so the client maps it onto `hostHeader` (a bare authority, needs `undici`, refused in a browser) and warns loudly, because a wrong `Host` at a multi-tenant proxy either 421s or lands your traffic on another tenant's cluster; the full contract is under [`hostHeader`](/reference/sdk/javascript#hostheader).
</Aside>

## Push

<Render file="snippets/js-push" />

`push()` takes one item or an array; body unwrapping (`data` / `payload` / the item itself)
and the client-minted UUIDv7 `transactionId` follow
[the shared grammar](/use/clients#same-grammar-six-spellings). A `traceId` (sent only when a
valid UUID) survives
[only the transaction path](/use/clients#verified-against-the-source): a plain push pops
back `traceId: null`.

`await` executes the builder; the result is the broker's array, one entry per item in
request order:

```js
const res = await client.queue('orders').push([{ data: { id: 1 } }])
// res[0] === { index: 0, message_id: '...', transaction_id: '...', queueName: 'orders', status: 'queued' }
```

`status` is `queued`, `duplicate`, `buffered` or `failed`. **A `buffered` item is on the
broker's disk spool, not stored, and the HTTP status is still `201`**: read `status` off the
array, the callbacks below never fire for it
([the status values](/use/concepts/producing#the-status-values)).

Your own `transactionId` makes a push idempotent inside the dedup window:

<Render file="snippets/js-push-dedup" />

Callbacks attached before the await split the response by status:

```js
await client
  .queue('orders')
  .push(items)
  .onSuccess(queued => metrics.add(queued.length))
  .onDuplicate(dups => log.warn({ n: dups.length }, 'already accepted'))
  .onError((failed, err) => log.error(err))
```

A `failed` item makes the await throw unless an `onError` callback is attached.

## Consume

<Render file="snippets/js-consume" />

`consume(handler)` starts `concurrency` workers and resolves only when every worker stops:
set `limit`, `idleMillis` or an `AbortSignal` to make it finish.

| Method | Default | Effect |
| --- | --- | --- |
| `.group(name)` | queue mode | Consumer group. Its cursor is what advances on ack. |
| `.concurrency(n)` | `1` | Independent poll loops. |
| `.batch(n)` | `1` | Messages per pop. |
| `.partitions(n)` | `1` | Claim up to `n` partitions per pop; `batch` is the global cap. |
| `.each()` | off | Call the handler once per message instead of once per batch. |
| `.limit(n)` | none | Stop the worker after `n` messages. |
| `.idleMillis(n)` | none | Stop the worker after `n` ms with no messages. |
| `.autoAck(bool)` | `true` | Ack on return, nack on throw. Client-side, never sent to the server. |
| `.wait(bool)` | `true` | Long-poll the pop. |
| `.timeoutMillis(n)` | `30000` | Long-poll window. Short values let a shutdown flag be observed sooner. |
| `.renewLease(true, ms)` | off | Renew the batch's lease every `ms` while the handler runs. |
| `.subscriptionMode(m)` | none (broker applies `new`) | `all` or `new`, applied only when the group's cursor is created. |
| `.subscriptionFrom(t)` | none | `now` or an ISO timestamp, same first-contact-only rule. |
| `consume(fn, { signal })` | n/a | An `AbortSignal` that stops every worker. |

Without `.each()` the handler receives the **array** of popped messages, even when `batch` is
`1`; [Python, Go and PHP differ](/use/clients#where-the-sdks-diverge).

`autoAck` is client-side: the worker acks `completed` on return, `failed` on throw. An ack
is an [offset commit](/use/concepts/ack), so a nack clamps the cursor at the failed message
and **everything after it in the popped batch is redelivered**: `.each()` abandons the rest,
otherwise the handler owns the whole batch. `.onSuccess()` or `.onError()` force `autoAck`
off; if the callback does not ack, the lease expires.

Delivered messages also carry a `trace()` method that never throws:

```js
await msg.trace({ traceName: ['tenant-acme'], eventType: 'step', data: { stage: 'charged' } })
```

## Pop

<Render file="snippets/js-pop" />

`pop()` resolves to an array of messages, or `[]`; message shape:
[What comes back](/use/concepts/consuming#what-comes-back).

`wait` defaults to `true`, so a bare `pop()` long-polls for 30 seconds; `.wait(false)`
returns immediately, `.timeoutMillis(n)` changes the window. `.batch(n)` caps the batch;
`.partitions(n)` claims up to `n` partitions under one shared `leaseId` with `batch` as the
global cap. `.group('name')` selects a group, queue mode without. `.autoAck(true)` commits
the cursor inside the pop:
[at-most-once delivery](/use/concepts/consuming#autoack-and-what-it-costs).

<Aside type="caution">
`pop()` swallows every failure into `[]`, including an exhausted `429` budget and a terminal `403`: an empty array does not mean an empty queue, so use `consume()` when failures must surface.
</Aside>

## Acknowledge manually

```js
const messages = await client.queue('orders').group('billing').batch(10).pop()
for (const msg of messages) { await handle(msg) }
await client.ack(messages, true, { group: 'billing' })
```

`ack(message, status, context)` takes one message or an array; `status` is `true`/`false` or
`completed`, `failed`, `retry`, `dlq`; `context.group` names the group, `context.error` the
failure reason stored on the DLQ row if the retry budget is exhausted.

`partitionId` is mandatory (a `transactionId` alone is not unique across partitions): a
batch ack throws without it, a single one returns `{ success: false }`, messages from a pop
carry it. **A rejected ack is still HTTP 200**: check `success` per item; a
length mismatch between request and response throws.

Per-message outcomes in one batch call:

```js
messages[0]._status = 'dlq'
messages[0]._error = 'unparseable payload'
await client.ack(messages, true, { group: 'billing' })
```

## Transactions

<Render file="snippets/js-transaction" />

`transaction()` bundles pushes and acks into one PostgreSQL transaction, all or nothing:
`.commit()` sends the collected `.queue(name).partition(p).push(items)` and
`.ack(messages, status)` operations plus the acked `leaseId`s as `requiredLeases`, so the
commit fails if a lease expired; committing with nothing throws. Ack input and push output
atomically; it is
[not exactly-once end to end](/use/concepts/transactions#the-limit-this-is-not-end-to-end-exactly-once):
a retry after a lost response duplicates the pushes unless the `transactionId`s are
deterministic and inside the dedup window.

## Lease renewal

```js
await client.renew(messages)
```

`renew()` takes a lease ID, a message, or an array, and de-duplicates: a multi-partition pop
shares one lease, so one call covers the array. A `null` `newExpiresAt` means the lease
already expired
([extending a lease](/use/concepts/leases-retries-dlq#extending-a-lease)).

## Client-side buffering

```js
await client
  .queue('events')
  .buffer({ messageCount: 500, timeMillis: 200 })
  .push([{ data: { seen: Date.now() } }])
```

With `buffer()`, `push()` returns `{ buffered: true, count: N }` immediately; the messages
flush at `messageCount` (default `100`) or `timeMillis` (default `1000`), keyed per
`queue/partition`.

<Aside type="caution">
**A buffered push trades away the per-item `queued` / `duplicate` verdict and lives in process memory**: an unflushed buffer is lost if the process dies without `close()` ([buffering across the SDKs](/use/clients#where-the-sdks-diverge)).
</Aside>

Flush explicitly with `await client.queue('events').flushBuffer()` (one queue/partition) or
`await client.flushAllBuffers()`; `client.getBufferStats()` returns
`{ activeBuffers, totalBufferedMessages, oldestBufferAge, flushesPerformed }`.

## Admin

```js
const overview = await client.admin.getOverview()
const queues = await client.admin.listQueues({ limit: 50 })
const lagging = await client.admin.getLaggingConsumers(120)
```

`client.admin` covers the observability and management routes; the route list with access
levels is in [Reference](/reference). `admin.clearQueue()` and
`admin.moveMessageToDLQ()` call
[unregistered routes](/use/concepts/leases-retries-dlq#getting-a-message-out-of-the-dead-letter-queue)
and 404; `admin.retryMessage()` and `admin.deleteMessage()` are real.

## Dead-letter queue

```js
const { messages } = await client.queue('orders').dlq('billing').limit(50).offset(0).get()
```

`dlq()` reads `GET /api/v1/dlq` and swallows errors to `{ messages: [], total: 0 }`. `total`
is the page size, not the result set, and the broker reads only `queue`, `consumerGroup`,
`limit` and `offset`: page until a short page, filter the rest client-side
([reading the DLQ](/use/concepts/leases-retries-dlq#reading-the-dead-letter-queue)).
`admin.retryMessage(partitionId, transactionId)`
[replays one dead letter](/use/concepts/leases-retries-dlq#getting-a-message-out-of-the-dead-letter-queue)
as a new message at the tail of its partition; no bulk redrive, so replay many rows by
reading and pushing them yourself.

## 429 and 403

```js
const client = new Queen({
  url: 'https://cell.example',
  bearerToken: token,
  retry429: { maxAttempts: 20, baseMs: 500, capMs: 30000 },
})
```

A `429` retries in place with `Retry-After` or jittered exponential backoff; `maxAttempts`
defaults to 10, and a long-poll pop retries unboundedly unless you set it
([the contract](/reference/errors#the-429-contract)). A `403` (`cluster_suspended`,
`storage_quota_exceeded`, `feature_gated`, `forbidden`) is terminal: the consume worker
throws out of the loop. Errors carry `.status` and `.code`.

## Logging

```js
const client = new Queen({ url, logger: pino(), structuredLogs: true })
```

Console logging is off unless `QUEEN_CLIENT_LOG=true` (Node) or
`window.QUEEN_CLIENT_LOG === true` (browser); a passed `logger` overrides the gate, needs
`info`/`warn`/`error` (`debug` falls back to `info`), and `structuredLogs: true` calls it
pino style, `info(fields, message)`.

## Graceful shutdown

```js
await client.close()
```

`close()` flushes and tears down every buffer, removes the signal handlers and destroys the
HTTP agent; without it the `undici` keep-alive sockets pin the event loop and the process
never exits. By default the constructor hooks `SIGINT`/`SIGTERM` to `close()` and exit (a
second signal exits with code 1); embedded in an app with its own lifecycle, pass
`handleSignals: false` or call `client.disableGracefulShutdown()`
(`enableGracefulShutdown()` reverses it).

## Streaming

```js
import { Stream } from 'queen-mq'

const stream = Stream.from(client.queue('events').group('agg'))
```

The windowed streaming SDK ships in the same package and builds on the same client; its
concepts are documented in [Use Queen](/use).
