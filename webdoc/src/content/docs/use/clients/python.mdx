The Python client is async throughout, built on `httpx`: every network call is a coroutine,
the builders are synchronous until the awaited terminal operation. It requires Python 3.9 or
newer; the surface mirrors JavaScript in `snake_case`, with the differences listed
[below](#differences-from-javascript).

```bash
pip install queen-mq
```

```python
from queen import Queen

client = Queen("http://localhost:6632")
```

It also exports `Admin`, `Stream`, the gates, the `TypedDict` types and the five defaults
dicts.

## Construct a client

```python
client = Queen(
    urls=["http://broker-a:6632", "http://broker-b:6632"],
    bearer_token=os.environ["QUEEN_TOKEN"],
    timeout_millis=30000,
    load_balancing_strategy="affinity",
)
```

The first positional argument accepts a URL string, a list, or a dict; every option is also
a keyword argument, and keyword arguments win. One URL is a direct client, several build a
load balancer with failover, no `url`/`urls` raises `ValueError`. `Queen` is an async
context manager, the tidiest way to guarantee the buffers flush:

```python
async with Queen("http://localhost:6632") as client:
    await client.queue("orders").push([{"data": {"id": 1}}])
```

### Client options

Defaults come from `CLIENT_DEFAULTS` in `queen/utils/defaults.py`.

| Option | Default | What it does |
| --- | --- | --- |
| `url` / `urls` | none | Required. One backend or many. |
| `timeout_millis` | `30000` | Per-request timeout. A long-poll pop adds 5 s of slack. |
| `retry_attempts` | `3` | **Total** tries for `5xx` and network failures. |
| `retry_delay_millis` | `1000` | First retry delay; doubles per attempt. |
| `load_balancing_strategy` | `"affinity"` | `"round-robin"`, `"session"` or `"affinity"`. |
| `affinity_hash_ring` | `128` | Virtual nodes per backend on the affinity ring. |
| `enable_failover` | `True` | Try the next backend on `5xx` / network error. |
| `health_retry_after_millis` | `5000` | How long a backend stays marked unhealthy. |
| `bearer_token` | `None` | Sent as `Authorization: Bearer <token>`. |
| `headers` | `{}` | Extra headers on every request. |
| `retry_429` | `None` | `{"max_attempts": …, "base_ms": …, "cap_ms": …}`. |
| `transport` | `None` | An `httpx` transport override: `httpx.MockTransport` lets tests drive the whole builder stack with no broker. |

## Push

<Render file="snippets/py-push" />

`push()` takes one dict or a list; body unwrapping (`data` / `payload` / the dict itself)
and the client-minted UUIDv7 `transactionId` follow
[the shared grammar](/use/clients#same-grammar-six-spellings). A `traceId` (sent only when a
valid UUID) survives only the transaction path: a plain push drops it and it pops back
`null` ([verified](/use/clients#verified-against-the-source)).

The returned `PushBuilder` is awaitable and resolves to the broker's per-item array:

```python
res = await client.queue("orders").push([{"data": {"id": 1}}])
assert res[0]["status"] == "queued"
```

`status` is `queued`, `duplicate`, `buffered` or `failed`
([the status values](/use/concepts/producing#the-status-values)). Your own `transactionId`
makes a retry idempotent inside the dedup window:

<Render file="snippets/py-push-dedup" />

`on_success`, `on_duplicate` and `on_error` chain before the await and bucket the response
by status.

## Consume

<Render file="snippets/py-consume" />

Awaiting `consume(handler)` starts `concurrency` workers with `asyncio.gather` and returns
when they all stop; without `limit`, `idle_millis` or a `signal` it runs forever.

| Method | Default | Effect |
| --- | --- | --- |
| `.group(name)` | queue mode | Consumer group whose cursor advances on ack. |
| `.concurrency(n)` | `1` | Independent poll loops as asyncio tasks. |
| `.batch(n)` | `1` | Messages per pop. Also decides the handler signature. See below. |
| `.partitions(n)` | `1` | Claim up to `n` partitions per pop. |
| `.each()` | off | One message per handler call. |
| `.limit(n)` | `None` | Stop the worker after `n` messages. |
| `.idle_millis(n)` | `None` | Stop the worker after `n` ms with no messages. |
| `.auto_ack(bool)` | `True` | Ack on return, nack on raise (client-side). |
| `.wait(bool)` | `True` | Long-poll the pop. |
| `.timeout_millis(n)` | `30000` | Long-poll window. |
| `.renew_lease(True, ms)` | off | Renew the batch's lease every `ms` as a background task. |
| `.subscription_mode(m)` | `None` | `all` or `new`, applied only when the group's cursor is created. |
| `.subscription_from(t)` | `None` | `now` or an ISO timestamp, same first-contact-only rule. |
| `consume(fn, signal=event)` | none | An `asyncio.Event` that stops every worker when set. |

`auto_ack` is client-side: the worker acks `completed` on return, `failed` on raise. An ack
is an [offset commit](/use/concepts/ack), so a nack clamps the cursor at the failed message
and **everything after it in the popped batch is redelivered**: `.each()` abandons the rest.
`on_success` or `on_error` force `auto_ack` off, on the assumption that your callback acks.

Delivered messages carry an async `trace` entry that never raises:

```python
await msg["trace"]({"traceName": ["tenant-acme"], "eventType": "step", "data": {"stage": "charged"}})
```

## Pop

<Render file="snippets/py-pop" />

`pop()` returns a list of message dicts, or `[]`; message shape:
[What comes back](/use/concepts/consuming#what-comes-back).

`wait` starts at `True`, so a bare `pop()` long-polls for 30 seconds; `.wait(False)` returns
immediately, `.timeout_millis(n)` changes the window. `.batch(n)` caps the batch;
`.partitions(n)` claims up to `n` partitions under one shared `leaseId` with `batch` as the
global cap. `.group(name)` selects a group. `.auto_ack(True)` commits the cursor inside the
pop: [at-most-once delivery](/use/concepts/consuming#autoack-and-what-it-costs).

<Aside type="caution">
`pop()` catches every exception, prints `Pop failed: …`, and returns `[]`, including an exhausted `429` budget and a terminal `403`: an empty list does not mean an empty queue.
</Aside>

## Differences from JavaScript

**With `batch(1)` the handler gets one message, not a list**; `batch(n)` passes the list,
`.each()` always one at a time. JavaScript passes the array except under `.each()`, so check
a ported handler's signature
([handler shapes](/use/clients#where-the-sdks-diverge)).

```python
# single message
await client.queue("jobs").batch(1).consume(handler)          # handler(msg)
# list of messages
await client.queue("jobs").batch(50).consume(handler)         # handler(msgs)
# single message, one at a time, out of a batch of 50
await client.queue("jobs").batch(50).each().consume(handler)  # handler(msg)
```

**Signal handlers are always installed.** The constructor replaces `SIGINT`/`SIGTERM`
unconditionally, there is no `handle_signals=False`, and `close()` restores `SIG_DFL`; the
handler schedules `close()` on the running loop (or runs it and exits), a second signal
exits with code 1.

**No injectable logger, and some lines print to stdout regardless**: the built-in logger is
gated by `QUEEN_CLIENT_LOG=true`, but `close()`, a failed `pop()`, `trace()` or lease
renewal call `print(...)` unconditionally.

**No `client.stream()` or `client.consumer()`**: the streaming SDK is reached through
`Stream.from_(queue_builder)`.

Also absent: `host_header` and `structured_logs`; everything else in `CLIENT_DEFAULTS`
matches.

## Acknowledge manually

```python
messages = await client.queue("orders").group("billing").batch(10).pop()
for msg in messages:
    await handle(msg)
await client.ack(messages, True, {"group": "billing"})
```

`ack(message, status, context)` takes one message or a list; `status` is `True`/`False` or
`completed`, `failed`, `retry`, `dlq`; `context["group"]` names the group,
`context["error"]` the failure reason stored on the DLQ row if the retry budget is
exhausted. `partitionId` is mandatory: missing, it raises `ValueError` for a batch or
returns `{"success": False, "error": …}` for a single ack. Set `msg["_status"]` and
`msg["_error"]` for different outcomes in one batch call.

<Aside type="note">
A rejected ack arrives as HTTP 200 with `success: false` on the item, and this client does not scan the batch `results` for per-item failures the way JavaScript does: inspect `results` yourself if a rejected ack matters.
</Aside>

## Transactions

```python
await (
    client.transaction()
    .queue("stage-2").push([{"data": {"value": msg["data"]["value"] + 1}}])
    .ack(msg)
    .commit()
)
```

`transaction()` bundles pushes and acks into one PostgreSQL transaction, all or nothing.
`.queue(name)` returns a sub-builder whose `.partition(p)` and `.push(items)` hand the
parent back; `.ack(messages, status, context)` collects the acked `leaseId`s as
`requiredLeases`, so the commit fails if a lease expired. `context` uses `consumer_group`
(not `group`) here; committing with nothing raises. It is
[not exactly-once end to end](/use/concepts/transactions#the-limit-this-is-not-end-to-end-exactly-once):
a lost response plus a retry duplicates the pushes unless the `transactionId`s are
deterministic and inside the dedup window.

## Lease renewal

```python
await client.renew(messages)
```

`renew()` takes a lease ID, a message, or a list, and de-duplicates: a multi-partition pop
shares one lease, so one call covers the list. A `None` `newExpiresAt` means the lease
already expired
([extending a lease](/use/concepts/leases-retries-dlq#extending-a-lease)).

## Client-side buffering

```python
await (
    client.queue("events")
    .buffer({"message_count": 500, "time_millis": 200})
    .push([{"data": {"seen": time.time()}}])
)
```

With `buffer()`, `push()` returns `{"buffered": True, "count": N}` immediately; the
messages flush at `message_count` (default `100`) or `time_millis` (default `1000`), keyed
per `queue/partition`.

<Aside type="caution">
**A buffered push hides the per-item `queued` / `duplicate` verdict and lives in process memory**: an unflushed buffer is lost if the process dies without `close()` ([buffering across the SDKs](/use/clients#where-the-sdks-diverge)).
</Aside>

`await client.queue("events").flush_buffer()` flushes one address,
`await client.flush_all_buffers()` flushes everything, and `client.get_buffer_stats()`
returns `activeBuffers`, `totalBufferedMessages`, `oldestBufferAge` and `flushesPerformed`.

## Admin

```python
overview = await client.admin.get_overview()
queues = await client.admin.list_queues(limit=50)
lagging = await client.admin.get_lagging_consumers(120)
```

`client.admin` matches the JavaScript admin surface in `snake_case`, query parameters as
keyword arguments; the route list with access levels is in
[Reference](/reference). `admin.clear_queue()` and `admin.move_message_to_dlq()` call
[unregistered routes](/use/concepts/leases-retries-dlq#getting-a-message-out-of-the-dead-letter-queue)
and 404; `admin.retry_message()` and `admin.delete_message()` are real.

## Dead-letter queue

```python
result = await client.queue("orders").dlq("billing").limit(50).get()
```

`dlq()` reads `GET /api/v1/dlq` and swallows errors to `{"messages": [], "total": 0}`.
`total` is the page size, not the result set, and the broker reads only `queue`,
`consumerGroup`, `limit` and `offset`: page until a short page, filter the rest yourself
([reading the DLQ](/use/concepts/leases-retries-dlq#reading-the-dead-letter-queue)).
`admin.retry_message(partition_id, transaction_id)`
[replays one dead letter](/use/concepts/leases-retries-dlq#getting-a-message-out-of-the-dead-letter-queue)
as a new message at the tail of its partition; no bulk redrive, so replay many rows by
reading and pushing them yourself.

## Queue configuration

```python
await client.queue("orders").config({"lease_time": 300, "retry_limit": 5}).create()
```

`config()` merges over `QUEUE_DEFAULTS` and `create()` camelCases the keys before posting.
**`/api/v1/configure` is a [full replace](/reference/queue-options)**: a partial dict still
posts a complete object, but `dedupWindowSeconds` is not in `QUEUE_DEFAULTS` and resets to
3600 unless you pass it.

## 429 and 403

```python
client = Queen(
    url="https://cell.example",
    bearer_token=token,
    retry_429={"max_attempts": 20, "base_ms": 500, "cap_ms": 30000},
)
```

A `429` retries in place with `Retry-After` or jittered exponential backoff; `max_attempts`
defaults to 10, and a long-poll pop retries unboundedly unless you set it
([the contract](/reference/errors#the-429-contract)). A `403` (`cluster_suspended`,
`storage_quota_exceeded`, `feature_gated`, `forbidden`) is terminal: the consume worker logs
the `code` and re-raises. Exceptions carry the status on `error.response.status_code` and
the machine-readable `code`.

## Shutdown

```python
await client.close()
```

`close()` flushes every buffer, closes the `httpx` client and restores the default signal
handlers. `async with Queen(...)` calls it for you on exit.
