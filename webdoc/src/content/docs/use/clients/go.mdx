The Go client takes a `context.Context` on every call and separates building from
executing: a chain is inert until `Execute(ctx)`, `Pop(ctx)` or `Get(ctx)`. Go 1.24; the
only dependencies are `github.com/google/uuid` and `github.com/jackc/pgx/v5`.

```bash
go get github.com/smartpricing/queen/clients/client-go
```

```go
import queen "github.com/smartpricing/queen/clients/client-go"

client, err := queen.New("http://localhost:6632")
if err != nil {
    return err
}
defer client.Close(context.Background())
```

## Construct a client

```go
client, err := queen.New(queen.ClientConfig{
    URLs:                  []string{"http://broker-a:6632", "http://broker-b:6632"},
    BearerToken:           os.Getenv("QUEEN_TOKEN"),
    TimeoutMillis:         30000,
    LoadBalancingStrategy: "affinity",
    EnableFailover:        true,
})
```

`New` accepts a `string`, `[]string`, `ClientConfig` or `*ClientConfig` and returns an
error rather than panicking. Zero-valued fields fall back to `ClientDefaults`, so a partial
config is safe, except `EnableFailover` (see [Gotchas](#gotchas)).

### Client options

| Field | Default | What it does |
| --- | --- | --- |
| `URL` / `URLs` | none | Required. One backend or many. |
| `TimeoutMillis` | `30000` | Per-request timeout. A long-poll pop adds 5 s of slack. |
| `RetryAttempts` | `3` | Retries **after** the first attempt, for `5xx` and network failures, so `3` means four tries. A negative value means exactly one try. |
| `RetryDelayMillis` | `1000` | First retry delay; doubles per attempt. |
| `LoadBalancingStrategy` | `"affinity"` | `"round-robin"`, `"session"` or `"affinity"`. |
| `AffinityHashRing` | `128` | Virtual nodes per backend on the affinity ring. |
| `EnableFailover` | `false` on a bare struct | Try the next backend on `5xx` / network error. Set it explicitly. |
| `HealthRetryAfterMillis` | `5000` | How long a backend stays marked unhealthy. |
| `BearerToken` | `""` | Sent as `Authorization: Bearer <token>`. |
| `Headers` | `nil` | Extra headers on every request. |
| `MaxIdleConnsPerHost` | `256` | Go's own default is 2, which forces connection churn under concurrency. `MaxIdleConns` is set to four times this. |
| `MaxConnsPerHost` | `0` (unlimited) | Hard cap on connections per host. |
| `Retry429` | `nil` | `*Retry429Config{MaxAttempts, BaseMs, CapMs}`. |

## Push

<Render file="snippets/go-push" />

`Push` accepts one payload, a `[]interface{}` or a `[]map[string]interface{}`;
`.TransactionID(id)` and `.TraceID(id)` chain before `Execute`:

```go
responses, err := client.Queue("orders").
    Partition("acct-42").
    Push(map[string]interface{}{"id": 1}).
    TransactionID("order-1-created").
    Execute(ctx)
```

`Execute` returns `[]PushResponse`, one entry per item in request order, with the broker's
`status` ([the status values](/use/concepts/producing#the-status-values)).

## Consume

<Render file="snippets/go-consume" />

`Limit(1)` is what ends that loop: without it `Execute` long-polls for the next message.
A worker looks the same with `Concurrency(4)` and no limit.

`Consume` takes a `MessageHandler` (`func(context.Context, *Message) error`), once per
message; `ConsumeBatch` a `BatchMessageHandler`
(`func(context.Context, []*Message) error`), once per popped batch (`Batch(1)` arrives as a
one-element slice). `Execute(ctx)` starts `Concurrency` goroutines and
blocks until they stop (`Start` is an alias); cancelling the `ctx` stops them cleanly,
`ctx.Err()` filtered out.

| Method | Default | Effect |
| --- | --- | --- |
| `.Group(name)` | queue mode | Consumer group whose cursor advances on ack. |
| `.Concurrency(n)` | `1` | Worker goroutines, each with its own poll loop. |
| `.Batch(n)` | `1` | Messages per pop. |
| `.Partitions(n)` | `1` | Claim up to `n` partitions per pop; `Batch` is the global cap. |
| `.Each()` | off | Process one message at a time, and abandon the rest of the batch after a nack. |
| `.Limit(n)` | `0` (none) | Stop the worker after `n` messages. |
| `.IdleMillis(n)` | `0` (none) | Stop the worker after `n` ms with no messages. |
| `.AutoAck(bool)` | `true` | Client-side: ack on `nil`, nack on error. |
| `.Wait(bool)` | `true` for consume | Long-poll the pop. |
| `.TimeoutMillis(n)` | `30000` | Long-poll window. |
| `.RenewLease(true, ms)` | off | Renew the batch's lease every `ms` from a goroutine while the handler runs. |
| `.SubscriptionMode(m)` | `""` | `all` or `new`, applied only when the group's cursor is created. |
| `.SubscriptionFrom(t)` | `""` | `now` or an ISO timestamp, same first-contact-only rule. |

`AutoAck` is client-side: the worker acks `completed` on `nil`, `failed` on error. An ack
is an [offset commit](/use/concepts/ack): a nack clamps the cursor and **everything after
the failed message in the batch is redelivered**, which is why `.Each()` abandons the rest.

Every delivered message carries a trace method that never panics:

```go
_, _ = msg.Trace(ctx, queen.TraceConfig{
    TraceNames: []string{"tenant-acme"},
    EventType:  "step",
    Data:       map[string]interface{}{"stage": "charged"},
})
```

## Pop

<Render file="snippets/go-pop" />

That pop carries no `Group`, so it reads on the queue's own cursor; add `.Group("billing")`
to read on a consumer group's, and `.TimeoutMillis(n)` to change the long-poll window.

`Pop` returns `[]*Message` and propagates errors
([unlike JavaScript, Python and C++](/use/clients#where-the-sdks-diverge)). `.Batch(n)` caps
the batch; `.Partitions(n)` claims up to `n` partitions under one shared `LeaseID` with
`Batch` as the global cap. `.AutoAck(true)` commits the cursor inside the pop:
[at-most-once delivery](/use/concepts/consuming#autoack-and-what-it-costs).

## Gotchas

- **`EnableFailover` is off unless you set it**: the `false` zero value wins and a failing
  backend stays in rotation; set it `true` with multiple URLs
  ([details](/reference/sdk/go#clientconfig)).
- **A bare `Pop(ctx)` does not long-poll**: `Wait` falls back to `PopDefaults.Wait`
  (`false`); call `.Wait(true)`
  ([the one SDK that differs](/use/clients#where-the-sdks-diverge)).
- **`TransactionID` applies to the first pushed item only**; the rest of a slice gets fresh
  UUIDv7s, so push one at a time or use [the HTTP API](/use/clients/http).
- `RetryAttempts` counts retries **after** the first attempt; the other SDKs count total
  tries.
- `Message.Queue`, `RetryCount` and `ErrorMessage` stay zero after a pop; filled on a DLQ
  read ([verified](/use/clients#verified-against-the-source)).
- `SubscriptionModeNewOnly` (`"new-only"`) normalizes to `new` on current brokers; older
  ones fell through to `all` and delivered the whole backlog, prefer
  `queen.SubscriptionModeNew` there.
- `AutoAck` on: handler errors are nacked and swallowed, `Execute` returns `nil`; off: they
  propagate. Transient pop errors are logged, the loop continues.
- DLQ `Get` swallows errors into an empty response with a `nil` error: check
  `len(dlq.Messages)`.
- `Admin.RetryMessage` makes no request, only returns an error: replay via
  [the replay route](/use/concepts/leases-retries-dlq#getting-a-message-out-of-the-dead-letter-queue)
  or re-push the payload.
- `Create()` omits zero-valued fields and `/configure` is a
  [full replace](/reference/queue-options): send the complete configuration every call.

## Acknowledge manually

```go
responses, err := client.Ack(ctx, messages, true, queen.AckOptions{ConsumerGroup: "billing"})
```

`Ack` accepts `*Message`, `Message`, `[]*Message` or `[]Message`; `success` maps to
`completed`/`failed`, `AckOptions` carries `ConsumerGroup` and `Error` (stored on the DLQ
row when the budget is exhausted). **A rejected ack is still HTTP 200**: check
`responses[i].Success`, a `nil` error is not enough. `ValidateMessages` rejects a missing
`PartitionID` (a `TransactionID` alone is not unique across partitions); wire details under
[`Ack`](/reference/sdk/go#ack).

## Transactions

<Render file="snippets/go-transaction" />

`Transaction()` bundles pushes and acks into one PostgreSQL transaction, all or nothing;
acked messages contribute their `LeaseID` to `requiredLeases`, so the commit fails if a
lease expired. It is
[not exactly-once end to end](/use/concepts/transactions#the-limit-this-is-not-end-to-end-exactly-once):
a lost response plus a retry duplicates the pushes unless the `transactionId`s are
deterministic and still inside the dedup window.

## Lease renewal

```go
responses, err := client.Renew(ctx, messages)
```

`Renew` accepts a lease ID, a slice of IDs, or messages in any shape, and de-duplicates: a
multi-partition pop shares one lease, so one call covers the slice. Check `Success`, an
expired lease renews nothing
([extending a lease](/use/concepts/leases-retries-dlq#extending-a-lease)).

## Client-side buffering

```go
_, err := client.Queue("events").
    Buffer(queen.BufferConfig{MessageCount: 500, TimeMillis: 200}).
    Push(payload).
    Execute(ctx)
```

With `Buffer`, `Execute` returns one `PushResponse{Status: "buffered"}` per item
immediately; the messages flush at `MessageCount` (default `100`) or `TimeMillis` (default
`1000`), keyed per `queue/partition`.

<Aside type="caution">
**A buffered push hides the broker's per-item verdict and lives in process memory**: an unflushed buffer is lost if the process dies without `Close` ([buffering across the SDKs](/use/clients#where-the-sdks-diverge)).
</Aside>

`client.Queue("events").FlushBuffer(ctx)` flushes one address, `client.FlushAllBuffers(ctx)`
flushes everything, and `client.GetBufferStats()` reports
[the buffer stats](/reference/sdk/go#buffering).

## Queue configuration

```go
_, err := client.Queue("orders").Config(queen.QueueConfig{
    LeaseTime:  300,
    RetryLimit: 5,
}).Create().Execute(ctx)
```

Zero-valued fields are omitted and `/configure` is a
[full replace](/reference/queue-options): `QueueConfig{LeaseTime: 300}` sends `leaseTime`
only, so send the complete configuration every call. `Create().Execute(ctx)` adds
`configured: true` itself; the broker's response is merged underneath.

## Admin

```go
overview, err := client.Admin().GetOverview(ctx)
queues, err := client.Admin().ListQueues(ctx, queen.ListQueuesParams{Limit: 50})
```

`client.Admin()` is a superset of the JavaScript admin surface, adding Prometheus metrics,
the DLQ listing, per-partition seek and the analytics series
([method list](/reference/sdk/go#admin), access levels in [Reference](/reference)).
`ClearQueue()` and `MoveMessageToDLQ()` call
[unregistered routes](/use/concepts/leases-retries-dlq#getting-a-message-out-of-the-dead-letter-queue)
and 404; `RetryMessage` and `DeleteMessage` are real routes, but see [Gotchas](#gotchas).

## Dead-letter queue

```go
dlq, err := client.Queue("orders").DLQ("billing").Limit(50).Get(ctx)
```

DLQ messages *do* carry `Queue`, `RetryCount` and `ErrorMessage`, unlike a pop. `dlq.Total`
is the page size and the broker reads only `queue`, `consumerGroup`, `limit`, `offset`: page
until a short page, filter client-side
([reading the DLQ](/use/concepts/leases-retries-dlq#reading-the-dead-letter-queue)). Replay
means re-pushing the payload or calling the retry route (see [Gotchas](#gotchas)); the
result is a new message at the tail of its partition.

## 429 and 403

```go
client, err := queen.New(queen.ClientConfig{
    URL:         "https://cell.example",
    BearerToken: token,
    Retry429:    &queen.Retry429Config{MaxAttempts: 20, BaseMs: 500, CapMs: 30000},
})
```

A `429` retries in place with `Retry-After` or jittered exponential backoff; `MaxAttempts`
defaults to 10, and requests marked `WithLongPollRetry()` (pop and consume with `Wait` true)
retry unboundedly unless you set it
([the contract](/reference/errors#the-429-contract)). Errors from a non-2xx response are
`*HTTPError`:

```go
var httpErr *queen.HTTPError
if errors.As(err, &httpErr) {
    if httpErr.IsClusterSuspended() { return errStop }
    log.Printf("queen %d %s: %s", httpErr.StatusCode, httpErr.Code, httpErr.Error())
}
```

`StatusCode`, `Code`, `Body` and `RetryAfterSeconds` are exposed, so branch on the code. A
`403` (`cluster_suspended`, `storage_quota_exceeded`, `feature_gated`, `forbidden`) is
terminal: the consume worker returns it.

## Logging

`QUEEN_CLIENT_LOG` set to `debug` / `true` / `1`, `info`, `warn` or `error` enables the
built-in logger (anything else, including unset, disables it); `queen.SetLogLevel(...)`
changes it at runtime.

## Shutdown

```go
defer client.Close(context.Background())
```

The Go client installs **no signal handlers**: `defer client.Close(ctx)` in `main` plus your
own `signal.NotifyContext` is the pattern. `Close(ctx)` flushes every buffer, closes the
HTTP client, and errors if a flush failed. **A cancelled context passed to `Close` abandons
the final flush and loses the buffered messages.**
