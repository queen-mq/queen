The PHP client is a plain PSR-4 library, `Queen\` mapped onto `src/`, with an optional Laravel
layer on top. It needs PHP 8.3 and it is synchronous: every builder chain ends in an explicit
`execute()`, `pop()`, `get()` or `commit()`.

```bash
composer require smartpricing/queen-mq
```

```php
use Queen\Queen;

$client = new Queen([
    'urls' => ['http://broker-a:6632', 'http://broker-b:6632'],
    'bearerToken' => getenv('QUEEN_TOKEN'),
    'timeoutMillis' => 30000,
    'loadBalancingStrategy' => 'affinity',
]);
```

The constructor also takes a bare URL string or a list of URLs. One URL is a direct client, more
than one builds a load balancer that fails over on `5xx` and network errors. The whole option
table is in [Reference](/reference/sdk/php#constructor).

## Push

```php
$results = $client->queue('orders')
    ->partition('acct-42')
    ->push([['transactionId' => 'order-1-created', 'data' => ['id' => 1]]])
    ->execute();
```

The queue and the partition are created by that call. `execute()` returns the broker's array,
one entry per item, each carrying a `status` of `queued`, `duplicate`, `buffered` or `failed`.
Pass your own `transactionId` and a retry inside the dedup window writes nothing a second time.

## Consume

```php
$client->queue('jobs')
    ->group('workers')
    ->batch(10)
    ->each()
    ->consume(function (array $message) {
        process($message['data']);
    })
    ->execute();
```

`consume()` returns a builder and `execute()` runs the worker loop, blocking until a signal, a
`limit` or an idle timeout stops it. With `concurrency(1)` it is one synchronous loop; above 1,
Guzzle's async pool overlaps the long polls. A bare `pop()` makes the same claim without the
loop, long-polling for 30 seconds unless you pass `->wait(false)`.

## Acknowledge

`autoAck` is client-side: the loop acks `completed` when your closure returns, `failed` when it
throws. Turn it off and settle the batch yourself.

```php
$messages = $client->queue('orders')->group('billing')->batch(10)->pop();
$client->ack($messages, true, ['group' => 'billing']);
```

`ack()` takes one message array, a list, or a bare `transactionId`, and `partitionId` is
mandatory. An ack is an offset commit, so a nack clamps the group's cursor at the failed message
and everything after it in that batch comes back. A rejected ack still arrives as HTTP 200: read
`success` off each item.

## Laravel

- Auto-discovery binds `Queen\Queen` as a singleton and aliases the `Queen` facade, so inject
  the class or call `Queen::queue('orders')->push(...)->execute();`.
- `php artisan vendor:publish --tag=queen-config` publishes `config/queen.php`, which reads
  `QUEEN_URL`, `QUEEN_BEARER_TOKEN` and the retry and load-balancing variables.
- Set `QUEUE_CONNECTION=queen` and run the normal
  `php artisan queue:work queen --timeout=60`; Laravel jobs, delayed dispatch,
  backoff and failed-job events then use Queen as their backend. Keep
  `QUEEN_RETRY_AFTER` longer than the worker timeout.
- Laravel monitoring separates total `pending`, live-lease `processing` and
  claimable `ready`: `size()` includes total pending plus Laravel timers,
  `pendingSize()` reports ready, and `reservedSize()` reports processing. The
  delayed part uses one indexed timer count for the literal `laravel:` prefix;
  it pages old timer listings after an explicit `no_such_route`/`unsupported`
  or an exact legacy list page returned during a rolling upgrade, never after
  a transient or malformed response. The
  oldest-ready timestamp is a conservative queue-detail approximation; when
  ready is zero the driver skips that expensive detail request entirely.
- `php artisan queen:supervise` runs the Laravel/PHP supervisor. The separate
  `queen-supervisor` binary runs the same pools with a low-memory Rust master.
  The broker still owns no PHP process lifecycle.
- `php artisan queen:consume orders "App\\Queen\\OrderHandler" --group=processors --auto-ack`
  runs a handler class as a worker; without `--auto-ack` it acknowledges nothing and every
  message is redelivered.

### Laravel worker supervisor

Both engines consume the versioned configuration printed by:

```bash
php artisan queen:supervisor-config --pretty
```

This inspection form redacts tokens and header values. `--for-engine` includes
the credentials needed by a supervisor engine.

`balance=auto` dynamically distributes workers, `simple` keeps a fixed evenly
spread pool, and `off` gives every worker the ordered comma-separated queue list.
With `strategy=size`, the target follows group-specific `effectivePending` and
`target_jobs_per_process`. With `strategy=time`, it follows
`effectivePending × observed job runtime` and `target_clear_seconds`; worker
telemetry is best effort and falls back to `default_runtime_seconds`.
Both engines cap exponential restart backoff. The Rust engine alone opens a
circuit after five consecutive crashes and admits one probe after its cooldown;
the PHP engine keeps retrying at `restart_backoff_max` without an open/probe
state.

Run either engine from the Laravel application directory:

```bash
php artisan queen:supervise
queen-supervisor --php php --artisan artisan
```

Inspect or control either one through the shared private state directory:

```bash
php artisan queen:supervisor status --json
php artisan queen:supervisor status --check # non-zero unless live
php artisan queen:supervisor pause
php artisan queen:supervisor continue
php artisan queen:supervisor terminate
```

These process controls target Unix and require PHP `pcntl`. Configure multiple
broker endpoints with `QUEEN_URLS`. Both v2 engines build isolated depth clients
directly from each pool's resolved Queen `connections` entry, including its
endpoints and validated headers; neither reuses a worker's live Laravel client.
`QUEEN_SUPERVISOR_READ_BEARER_TOKEN` may replace the worker token with one that
has read access only. Both engines poll in waves of at most 16 concurrent depth
requests and fail over network/5xx errors. The resolved JSON contains the token
and custom headers only with `--for-engine`; prefer the one-shot Artisan pipe
and protect any credential-bearing persisted config with mode `0600`.

<Aside type="danger">
Run one supervisor replica per application/consumer group. The state-directory
lock excludes a second local process only; it is not a distributed leader
lease. Until Queen exposes a fenced supervisor lease, two masters on different
hosts can each react to the same global backlog and over-scale. Kubernetes
deployments should use one replica without surge overlap (for example,
`Recreate`). This restriction applies to the master, not to its worker count.
</Aside>

## What differs here

- A chain that never reaches `execute()` sends no request at all, and says nothing about it.
- Without `each()` the closure receives the array of popped messages, even when `batch` is `1`.
- `pop()` propagates exceptions instead of swallowing them into an empty array, and returns the
  result of `array_filter`, which keeps the original keys: use `array_values()` for a list.
- An `each()` handler keeps running after a nack, so make it idempotent or throw out of a batch
  handler instead.
- Signal handling needs the `pcntl` extension; without it only `limit` or `idleMillis` stops the
  consume loop.
