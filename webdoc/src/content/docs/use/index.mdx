Two of the semantics follow from the model rather than being options you can turn off:
**an acknowledgement is an offset commit**, and **a consumer group holds at most one leased
batch per partition**. Read the concept chain in order; everything after it (the SDK pages,
the examples, the error handling) assumes you know what a partition, a cursor and a lease are.

## Before you write code

Four things are worth knowing before the first request.

- **Everything is HTTP.** The SDKs are convenience layers over a small JSON API; there is no
  custom wire protocol and no persistent connection to manage. The full route table, with the
  access level each route requires, is in the [reference](/reference).
- **Clients hold no coordination state.** The broker hands out no partition assignments and
  runs no rebalancing protocol, so a worker that restarts does not stall its peers.
- **TLS terminates in front of the broker.** The broker has no TLS listener and no CORS layer,
  so terminate TLS at the proxy or at a reverse proxy in front of it. See
  [self-hosting](/selfhost).
- **`POST /api/v1/configure` is a [full replace](/reference/queue-options).** Any option you
  omit is reset to its default, so send the whole configuration every time.

## What "verified" means here

Code samples on these pages, including the two above, are extracted from files the test suite
executes and labelled with the file they came from; a sample without that label is
hand-written. The [worked examples](/use/examples) are built the same way, route and
environment tables are generated from the source at build time, and throughput figures live
in [benchmarks](/benchmarks) with the archived output that produced them.
