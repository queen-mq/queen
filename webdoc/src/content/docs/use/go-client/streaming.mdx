The four tutorials before this one move messages. This one aggregates them: a streaming query
reads a queue, keeps window state per partition, and pushes each closed window to an output queue.

The state, the output and the acknowledgement of the inputs commit in the same PostgreSQL
transaction, which is exactly-once aggregation with no changelog topic and no state store to size
and operate: the state and the queue are already in the same database.

The query is built from the same queue builders, adapted with `AsStreamSource()`, and `Run`
returns as soon as it is registered, with the pop loop in its own goroutine. The program owns the
shutdown through `runner.Stop()`, and has to let that loop poll once before producing: the first
poll is what creates the stream's consumer group, and a new group starts at the tail.

`Aggregate` takes the field order after the map of extractors, because Go map iteration is random
and a query's identity is a hash of its configuration. Leave it out and the client falls back to
alphabetical, which is stable but is not what the same query written in JavaScript hashes to. The
extractors receive the message payload itself, not the envelope, which is silent when you get it
wrong because a missing field aggregates to zero.

## Run it

Against a broker from [the quickstart](/start/quickstart), from `examples/tutorials/go`:

```bash
GOWORK=off go run ./streaming
```

The program checks its own outcome and exits non-zero if a check fails. Every tutorial in this
section runs in the repository's own suite: `examples/tutorials/run.sh go`.
