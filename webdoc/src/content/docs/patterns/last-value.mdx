The availability of a hotel changes many times a minute. A screen that shows it needs only the current value, and handling every old update on the way there is wasted work.

A consumer group with `.conflation()` gets only the newest message of each partition, and its cursor moves past the older ones.

<Fig id="last-value" caption="Conflation: the newest value of each partition, for this group only." />

<SdkCode id="uc-latest" />

Three updates were pushed (12, 11 and 9 rooms). The screen got 9, and the older two were never delivered to it.

<Why>for a value that changes, only the last one matters. Conflation lets a slow consumer catch up in one step instead of replaying every update. Other groups of the same queue still get every message.</Why>

One thing to know: use it only where an old message has no meaning of its own. For events that each count, such as payments, every message must be handled.
