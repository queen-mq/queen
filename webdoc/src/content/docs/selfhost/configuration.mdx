There is no configuration file and there are no command-line flags. Every knob
is an environment variable, read once by `config::load()` before the HTTP
listener binds; changing a variable means restarting the process. The one
accepted argument, the subcommand `migrate`, only reports that offline migration
was retired with the previous storage engine, and exits 1 without touching the
database.

The design goal is that a broker never runs in a state you did not ask for:
booleans parse strictly, and every boot prints the configuration that was
actually understood. Whenever a setting seems ignored, start here:

```bash
docker logs queen 2>&1 | grep -E 'FATAL|config:'
```

## The broker prints its effective configuration

After the JWT configuration is validated and before any background service
starts, the broker emits one block per subsystem on the `boot` target, carrying
the values it resolved rather than the values you wrote:

```text
config: server    config: postgres    config: auth       config: sync
config: engine    config: flow        config: jobs       config: file_buffer
config: security  config: logging
```

A misspelled variable shows up as a default; a value that arrived through a
legacy alias shows up under the new name. Secrets (`JWT_SECRET`, `PG_PASSWORD`,
`QUEEN_ENCRYPTION_KEY`, `QUEEN_SYNC_SECRET`) render as `<unset>` or
`<set:64 chars>`, never as values. `QUEEN_LOG_JSON=1` emits the same content as
one JSON object per line.

## One boolean parser, three outcomes

Every boolean in the broker resolves through the same function, so `=on`, `=1`
and `=true` mean the same thing everywhere. Accepted spellings are `true/false`,
`1/0`, `yes/no`, `on/off`, case-insensitive, whitespace trimmed.

| Value | Result |
| --- | --- |
| A recognised spelling | Used. |
| Unset, or present but empty or whitespace-only | The documented default. `JWT_ENABLED=` in a Compose file means "leave it alone", not `false`. |
| Anything else | **Fatal.** The process logs `FATAL: JWT_ENABLED="maybe" is not a boolean (expected true/false, 1/0, yes/no, on/off)` and exits 1. |

Refusing to guess is the only outcome safe in both directions: a permissive
parser can turn a typo into an accidental authentication *enable*, and a silent
fallback once turned `JWT_ENABLED=1` into a broker running with authentication
**off**, silently. The three booleans read outside `config.rs`
(`QUEEN_LOG_JSON`, `QUEEN_APPLY_SCHEMA`, `QUEEN_V2_BUNDLE_LOG`) are validated
eagerly with the rest, so every boolean mistake surfaces on the same boot.

<Aside type="caution">
**Numbers are parsed leniently.** An unparseable integer or float silently
resolves to its default: `DB_POOL_SIZE=16O` (with a letter O) yields 160, not an
error. Interval and size knobs are floored at 1, `STATS_INTERVAL_MS` and
`METRICS_FLUSH_MS` at 1000 ms, with a below-floor value raised silently. The
protection against a numeric typo is the boot block above, not the parser.
</Aside>

Strings differ again: a present-but-empty string is kept verbatim, not treated
as unset; that is how `JWT_SKIP_PATHS=""` clears the default skip list. The one
exception is `PG_DATABASE`, which resolves through a non-empty chain
(`PG_DATABASE`, then the legacy `PG_DB`, then `postgres`) instead of naming a
database called `""`.

## What kills the boot

The broker prefers to die at startup over serving in a state you did not ask
for. Four things exit 1:

1. An unparseable boolean, as above.
2. `JWT_ENABLED=true` with no usable key material for the configured algorithm,
   or an unrecognised algorithm. The message names the missing credential.
3. A schema apply failure, unless `QUEEN_APPLY_SCHEMA=0` skips the apply.
4. Failure to bind `0.0.0.0:$PORT`.

And one thing that does **not**: a `QUEEN_ENCRYPTION_KEY` that is not exactly
64 hex characters logs a single warning and
[**silently disables encryption**](/selfhost/security/encryption#a-bad-key-silently-stores-plaintext),
so flagged queues store plaintext while their pushes keep returning success.

A release build sets `panic = "abort"`: a panic in any detached background loop
aborts the whole process, after a structured `ERROR` on the `panic` target. The
supervisor restarts the process and startup recovery drains any spooled pushes,
so "the broker is up" and "every background job is running" are the same
statement.

## The knobs that matter

Most environment variables are measured engine tuning that should be left
alone. A deployment touches variables from these groups only.

| Purpose | Variables |
| --- | --- |
| Reach PostgreSQL | `PG_HOST`, `PG_PORT`, `PG_USER`, `PG_PASSWORD`, `PG_DATABASE` |
| Size the pool, bound statements | `DB_POOL_SIZE`, `QUEEN_STMT_TIMEOUT_MS` |
| Encrypt broker-to-PostgreSQL traffic | `PG_USE_SSL`, `PG_SSL_REJECT_UNAUTHORIZED` |
| Serve on a different port | `PORT` |
| Accept larger bodies | `QUEEN_MAX_BODY_BYTES` |
| Turn on authentication | `JWT_ENABLED`, `JWT_ALGORITHM`, then `JWT_SECRET` or `JWT_PUBLIC_KEY` or `JWT_JWKS_URL` |
| Run more than one broker | `QUEEN_MESH_PEERS`, `QUEEN_MESH_PORT`, `QUEEN_SYNC_SECRET`, `QUEEN_SERVER_ID` |
| Survive a database outage | `FILE_BUFFER_DIR`, which must be writable and persistent |
| Change the maintenance cadence | `RETENTION_INTERVAL`, `RETENTION_BATCH_SIZE` |
| Encrypt payloads at rest | `QUEEN_ENCRYPTION_KEY` |
| Shape the logs | `LOG_LEVEL`, `QUEEN_LOG_JSON`, `QUEEN_LOG_RATES_MS`, `QUEEN_LOG_TOPN_QUEUES` |
| Let a privileged role own the DDL | `QUEEN_APPLY_SCHEMA` |
| Scope queues by tenant behind a proxy | `QUEEN_TENANCY_HEADER` |

`LOG_LEVEL` accepts full `EnvFilter` syntax (`info,queen::pop=debug` works);
`RUST_LOG` takes precedence, and an unparseable filter falls back to `info`.
`QUEEN_SERVER_ID` names this instance in mesh heartbeats and peer statistics:
unset, the broker uses `HOSTNAME`, and with neither it generates
`queen-<8 hex>`. Nothing routes on the value.

## Names with a history

Several settings are reachable under two names. Both read the same value; the
precedence is fixed and not always the newer name.

| Setting | Names | Precedence |
| --- | --- | --- |
| Mesh peer list | `QUEEN_MESH_PEERS`, `QUEEN_UDP_PEERS` | `QUEEN_MESH_PEERS` wins when non-empty. The transport is framed TCP; only the variable name is a survivor of the UDP era. |
| Mesh port | `QUEEN_MESH_PORT`, `QUEEN_UDP_NOTIFY_PORT` | `QUEEN_MESH_PORT` wins. Default 6633. |
| Database name | `PG_DATABASE`, `PG_DB` | `PG_DATABASE`, then `PG_DB`, then `postgres`. |
| Pop long-poll timeout | `DEFAULT_TIMEOUT`, `POP_DEFAULT_TIMEOUT_MS` | **`DEFAULT_TIMEOUT` wins.** Setting only `POP_DEFAULT_TIMEOUT_MS` has no effect if `DEFAULT_TIMEOUT` is also set. Default 30000 ms. |

## Variables you may see in older manifests

Four categories, and the difference between them matters when you inherit a
manifest from an older deployment.

| Category | Variables | What to know |
| --- | --- | --- |
| Experiment-only overrides | `QUEEN_V2_FUSION_SHARDS`, `QUEEN_V2_FUSION_FRAMES`, `QUEEN_V2_FUSION_HOLD_MS`, `QUEEN_V2_FUSION_MAX_INFLIGHT`, `QUEEN_V2_BUNDLE_MAX`, `QUEEN_V2_BUNDLE_LOG`, `QUEEN_V2_FUSION_MIN_FRAMES`, `QUEEN_V2_FUSION_MIN_WAIT_MS`, `QUEEN_V2_ZSTD_LEVEL`, `QUEEN_ADMISSION_MIN` / `QUEEN_ADMISSION_INIT` / `QUEEN_ADMISSION_MAX`, `QUEEN_ADMISSION_SHARE_{PUSH,POP,ACK,MAINT}` | The fusion and adaptive-concurrency engine self-tunes; these exist so a benchmark can pin a value, and the source states they are not part of the product contract. Setting them is supported; treating a value from a blog post as a tuning recommendation is not. |
| Removed in 1.0.0-beta.2 | `QUEEN_SEG_{PUSH,POP}_{INIT,MIN,MAX}`, `QUEEN_VEGAS_ALPHA`, `QUEEN_VEGAS_BETA` | Configured the two Vegas limiters that the single [admission arbiter](/internals/flow-control) replaced. No longer read; the broker logs a boot warning if it finds any of them set. |
| Read but inert | `QUEEN_V2_FUSION_FRAMES` | Parsed and printed at boot, no longer a flush trigger. `RETENTION_PARALLELISM` and `PARTITION_CLEANUP_DAYS` left this list in 1.0.0: the first is the [retention fan-out width](/selfhost/retention), the only lever that raises the deletion rate. |
| Not read at all | `QUEEN_STATIC_DIR` | Configures nothing. The dashboard is compiled in with `rust_embed`, there is no runtime static-directory override, and the published image deliberately does not set it. |

The full list of every variable with the default the code applies is generated
from `config.rs` at build time; see the
[configuration reference](/reference/config/). A variable in neither that table
nor the categories above is not read by the broker.
