The broker is one process with one plaintext listener: it binds `0.0.0.0:PORT`
(6632) with plain TCP, serves the HTTP API and the dashboard from that port, and
authenticates callers only once `JWT_ENABLED` is on. There is no TLS listener and
no CORS layer in the binary, so every security property of a Queen deployment is a
decision you make around the broker.

The hardened boot, in one command. Generate both secrets and keep them:

```bash
JWT_SECRET="$(openssl rand -hex 32)"
QUEEN_ENCRYPTION_KEY="$(openssl rand -hex 32)"
echo "JWT_SECRET=$JWT_SECRET"
echo "QUEEN_ENCRYPTION_KEY=$QUEEN_ENCRYPTION_KEY"
```

```bash
JWT_ENABLED=true JWT_ALGORITHM=HS256 JWT_SECRET="$JWT_SECRET" \
  PG_USE_SSL=true \
  QUEEN_ENCRYPTION_KEY="$QUEEN_ENCRYPTION_KEY" \
  server/target/release/queen
```

Confirm two boot lines before trusting either flag: `JWT auth ENABLED` with the
algorithm you meant, and `encryption service initialized (AES-256-GCM)`.
Encryption also needs a per-queue flag: see
[Payload encryption at rest](/selfhost/security/encryption).

## The boundaries, listed

| Surface | Port | What the broker enforces | What you must add |
| --- | --- | --- | --- |
| HTTP API + dashboard | `PORT` (6632) | Optional JWT with a per-route access level | TLS termination; network policy |
| Broker → PostgreSQL | 5432 | Optional TLS (`PG_USE_SSL`), optional chain validation | A database role with the right grants |
| Mesh (multi-broker) | `QUEEN_MESH_PORT` (6633) | An HMAC'd HELLO handshake, then nothing | A firewall. This one is not optional |
| Payload at rest | n/a | Optional AES-256-GCM on flagged queues | Key management, and a check that the key took effect |
| Multi-tenant separation | n/a | `x-queen-tenant` scoping, when enabled | A gateway that is the only thing allowed to set that header |

## A posture that holds

<Steps>

1. Bind the broker to a private interface, or firewall `PORT` to the clients that
   need it. The mesh port goes to peers only.

2. Terminate TLS in front. With tenants, that terminator is the proxy:
   [Running Queen as a multi-tenant service](/selfhost/multi-tenant).

3. Turn on `JWT_ENABLED` and give each client the narrowest role that works.

4. Set `PG_USE_SSL=true` if the database is not on localhost, and choose the
   verification mode deliberately.

5. Keep `/metrics/prometheus` off any network a tenant or customer can reach.

6. Verify the encryption boot log line before you trust the flag.

</Steps>

## The listener is plaintext HTTP

`axum::serve` runs on a `tokio::net::TcpListener`; nothing in the broker reads a
certificate. Terminate HTTPS in front: the multi-tenant proxy
(`QUEEN_PROXY_TLS_CERT` / `QUEEN_PROXY_TLS_KEY`, see
[Deploying queen_proxy](/selfhost/multi-tenant/proxy)) or any reverse proxy you
already run. There is no CORS layer either, so a browser on another origin fails
its preflight; a non-browser client is unaffected.

## The dashboard and the API share the port

Any request that matches no route is answered from the dashboard assets compiled
into the binary, with `index.html` as the last resort; paths under `/api/` or
`/auth/`, and methods other than `GET`/`HEAD`, get a JSON
`404 {"error":"Not Found","code":"no_such_route"}` instead. So the API and the
dashboard are exposed together: if they need different audiences, that split
happens in front of the broker.

## Authentication is off by default

With `JWT_ENABLED=false` (the default) the auth middleware is a pass-through:
every route is open to anything that can open a TCP connection, including
`DELETE /api/v1/resources/queues/:queue` and `POST /api/v1/system/maintenance`,
and the [dashboard](/selfhost/dashboard) boots as a full-admin standalone
identity. The boot log states this mode in one line.

Turning it on gives you a per-route access level and five roles that are a set,
not a ladder. [Broker authentication](/selfhost/security/jwt) covers the
algorithms, JWKS rotation, the role model, boot-time validation, and the routes
that stay public with JWT on: `/health`, the metrics endpoints, the dashboard
shell, and the three `/auth/*` identity routes.

**`/metrics/prometheus` is public, and its per-queue series sum across tenants
with no tenant label, so on a shared deployment it leaks every tenant's queue
names and volumes: restrict it at the network layer.** See
[Observability](/selfhost/observability).

## The mesh port is a control surface

Multi-broker notifications travel over framed TCP on `QUEEN_MESH_PORT` (6633);
the `HELLO` handshake is replayable and post-handshake frames, maintenance-mode
flips included, are unauthenticated JSON.
**[The mesh port must be firewalled to the broker peers themselves](/selfhost/ha#the-mesh-port-must-be-firewalled).**

## `x-queen-tenant` is not a credential

With `QUEEN_TENANCY_HEADER=true` the broker validates the header for shape (a
malformed value is a `400`, an absent one means the default tenant) and against
nothing else: any caller that can reach the broker can name any tenant. That is
intentional. The trust boundary is the gateway that sets the header plus the
bearer secret the gateway presents, which is why native tenancy is an operator
feature and never a client-facing one. See
[Broker-native tenancy](/selfhost/multi-tenant/broker-tenancy).

## PostgreSQL is inside the boundary

The broker needs `CREATE SCHEMA` on first boot and no extensions, and connects
with `PG_USE_SSL` off by default, meaning plaintext until you turn it on:
[PostgreSQL TLS](/selfhost/security/postgres-tls) covers the two modes and what
each proves.

One schema is granted broadly: `002_streams_schema.sql` grants `USAGE` on
`queen_streams` and `SELECT, INSERT, UPDATE, DELETE` on `queen_streams.queries`
and `queen_streams.state` to `PUBLIC`, so any role with a connection to that
database can read and rewrite stream definitions and stream state regardless of
what the HTTP layer allows, and retention never touches that state.

Payload encryption is the one thing that survives a database compromise, and only
for flagged queues. Read its failure mode before you rely on it:
[Payload encryption at rest](/selfhost/security/encryption).
