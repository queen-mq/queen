# Rows window (cluster version 6): a push's index row leaves the store when
# the queue's dedup window has passed, and a consumer behind it reads from the
# queue log. Branch improvestorage, 2026-10-09.
#
#   cd /root/jepsen-rows && RUNS=/root/runs-rows BIN=/root/bin/queen-rows ./run-campaign.sh matrix-rows.txt
#
# 1. Two smokes: the harness, the binary and the new option.
# 2. R: the consumption workloads with rows that live 2 seconds
#    (--dedup-window 2, QUEEN_RAFT_TXN_WINDOW_MIN_S=2, a retention scan every
#    second) and 256 KiB log files sealed after 10 s, so that consumers read
#    messages without rows after every fault and in the final drain, the
#    cross-file directory is built, and snapshots and log cuts meet it.
#    W8 retention sets its own 5 s dedup window; W7 dlq keeps the 24 h one.
#    The queue workload runs on 400 partitions and the pipeline on 200: on
#    the default 8 (4) the consumers keep up and almost never read a message
#    whose row is gone (the first launch showed 0 claims from the queue log).
#    A dequeue takes a random partition, so with 400 of them at rate 200 a
#    message waits a few seconds: about half the claims find rows and half
#    do not, and many batches cross the line between the two.
# 3. D: the default configuration on the same binary (rows never expire in a
#    5-minute test): what 2.1.0 passed must still pass.
