# W12 standby variants (workload/failover.clj), before a paid Jepsen analysis
# (2026-11-13): what the failover campaigns of October left out. Six nodes:
# n1 to n3 are the source, n4 to n6 the standby.
#
#   NODES=n1,n2,n3,n4,n5,n6 RUNS=/root/runs-standby BIN=/root/bin/queen-fix1 \
#     ./run-campaign.sh matrix-standby-2026-11-13.txt
#
# Then the October suite on the same build: matrix-failover.txt.
#
# What each section adds to the October checks (no write answered by a standby
# before its promotion; the promoted log a prefix of the source's; a
# transaction whole or absent; a planned switch loses nothing; after a crash
# nothing older than the lost tail; the promoted cluster keeps its writes):
#
# 1. Smoke, no other fault. Read them before the rest: `replayed` and
#    `own-acked` above 0; a seeded test shows `seeded` and `grown` with every
#    group's voters [1 2 3]; a --w12-kv test shows `kv-counted` on both
#    clusters.
# 2. --w12-kv: every send is one transaction that also increments a KV
#    counter, so a replay and a promotion carry a record and its count
#    together. Judged: in each cluster every counter equals its partition's
#    record count, and the nodes of one cluster read the same counters.
# 3. --standby-seed: a standby of a source that already purged the start of
#    its log (QUEEN_RAFT_LOG_KEEP=16, QUEEN_RAFT_PURGE_HOLD_S=5), seeded from
#    a snapshot at a quarter of the run (every standby node starts; node 1
#    seeds once the others answer that they hold nothing), grown to three
#    voters 15 s later, under the same faults. Judged besides: the seed and
#    the growth went through, and no follower halted. Between the seed and
#    the standby's first read only the source node that sent the snapshot
#    holds its log for the standby: the kills of section 3 test that window.
# 4. Four tenants on two raft groups on both clusters: each group is followed
#    and promoted at its own point. The crash check compares the sends of one
#    group only; a transaction stays in one tenant.
# 5. A rolling upgrade of both clusters from /root/bin/queen-old, the standby
#    first (the documented order) or the source first (the standby then
#    waits, counted in `link-waiting-seen`), and the failover after it or in
#    the middle of it.
#
# 6 tests of 180 to 240 s, 19 of 300 s, 6 of 300 to 400 s, each with about 2 minutes of
# setup and final reads: about 3 hours 40.
