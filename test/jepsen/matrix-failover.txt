# W12 failover: a standby cluster is promoted (workload/failover.clj).
# Six nodes: n1 to n3 are the source, n4 to n6 the standby.
#
#   cd /root/jepsen-failover && NODES=n1,n2,n3,n4,n5,n6 RUNS=/root/runs-failover \
#     BIN=/root/bin/queen ./run-campaign.sh matrix-failover.txt
#
# Every test: the standby follows for half the time limit while the other
# faults run on both clusters, then the failover, then the promoted cluster
# serves under the same faults. What is judged: no write answered by a standby
# before its promotion; the promoted log is a prefix of the source's, record
# for record; a transaction whole or absent; a planned switch loses nothing;
# after a crash no acknowledged write is missing while a later one is there;
# the promoted cluster keeps its own writes.
#
# 1. Smoke, no other fault, 3 minutes each. Read both results before the rest
#    runs: `replayed` and `own-acked` must be above 0 (the checker answers
#    unknown, not valid, when they are not), and a crash must show a
#    `lost-count` that fits `link-before-stop`.
# 2. A crash of the source while faults run.
# 3. A planned switch, with faults before and after it.
# 4. Transactions across partitions: one log entry each.
# 5. The same again, for the tests whose outcome depends most on timing.
# 6. A crash that finds the standby 10 s behind (--failover crash-behind: the
#    two clusters cannot hear each other for 10 s, then the source dies). On a
#    healthy pair the standby is milliseconds behind and sections 2 to 5 lose
#    nothing; these lose about 10 s of writes, and what is judged is that
#    nothing older is lost and that a transaction is lost whole.
#
# 2 tests of 180 s and 25 of 300 s: about 2 hours 30.

# --- 1. smoke
fo-crash-smoke          --workload failover --standby-nodes 3 --failover crash --nemesis none --time-limit 180 --rate 200
fo-planned-smoke        --workload failover --standby-nodes 3 --failover planned --nemesis none --time-limit 180 --rate 200
