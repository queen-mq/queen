# Locks: the build that adds POST /api/v1/locks, the KV `check` op and
# cluster version 5.
#
#   cd /root/jepsen-locks && RUNS=/root/runs-locks BIN=/root/bin/queen-locks ./run-campaign.sh matrix-locks.txt
#
# 1. Smoke, no faults, 2 minutes each: the new workloads' own plumbing. Read
#    the two results before the rest runs: `records` and `steps-fenced` must
#    both be above 0, or the run shows nothing (the checker then answers
#    unknown, not valid).
# 2. W11 locks and W11b semaphore under the P10 fault set. What is judged:
#    tokens along a guarded resource never go back, one owner per token, no
#    record of a step that rolled back, tokens rise from grant to grant, and
#    no permit is handed over before its lease could have ended. That last one
#    is not judged under clock faults (early-judged? false in the result).
# 3. The KV and transaction workloads again. The planner changed twice for
#    this build: a call whose writes all lose beside a read now logs a no-op
#    for its position, and `check` is a new command shape a follower may only
#    forward at cluster version 5.
#
# 4. More of the same, queued behind the first three while the droplets are
#    up: every fault at once, offload off, the composite faults, one planner
#    lane, and the semaphore under the faults section 2 gave the lock only.
#
# 38 tests of 300 s and 2 of 120 s: about 3 h 45 at the 5.7 minutes a test
# the 2.0.1 campaign took.
