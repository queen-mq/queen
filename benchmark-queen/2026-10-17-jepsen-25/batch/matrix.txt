# Batched pushes (2026-10-15), for the build of branch worktree-bytes-per-msg ("2.4"): every test
# of matrix-220.txt pushes ONE message per push, and a one-message push keeps its version-1
# outcome, so none of them writes a push outcome as runs (catalogue version 7, rsm/entry.rs
# PushOutcome::planned). These tests do: --batch-sends N makes every push carry several messages
# of one partition (log: 1 to N sends to one key; dedup: 2 to N distinct ids of one partition).
# The snapshot test ships checkpoints whose request_ids rows are runs; the restart, kill and
# lazyfs tests reopen them; the rw test lets rows leave the store at a 2 s window.
#
#   cd /root/jepsen-batch && RUNS=/root/runs-24-batch BIN=/root/bin/queen-24 NODES=n1,n2,n3,n4,n5 ./run-campaign.sh matrix-24-batch.txt
